## Objetivo

Al terminar este proyecto tendrás la app de notas organizada por features y capas, con notas en SQLite, una feature de frases que consume una API pública con TanStack Query y caché persistente, y un formulario validado con zod.

**Prerrequisitos:** `05-estado-datos-arquitectura/09-react-hook-form-y-zod`

## Concepto

Este proyecto parte de la app que construiste en [Proyecto: app de notas local](/etapa/04-react-native-expo/11-proyecto-app-de-notas). Esa app funciona, pero guarda las notas en memoria y toda la lógica vive en las pantallas. Ahora vas a aplicar cada lección de esta etapa sobre ella, sin agregar pantallas complicadas: el reto está en la estructura, no en la interfaz.

Piensa en una mudanza a una casa más grande. No compras muebles nuevos: llevas los que tienes, pero esta vez cada uno va a una habitación con un propósito, las cosas de valor van a la caja fuerte y la despensa se llena con lo que traes del mercado. La app hace lo mismo con su código y sus datos.

### Qué vas a construir

1. **Estructura por features.** Mueve el código a `src/features/notes` con las capas `domain`, `application`, `infrastructure` y `ui`. Las rutas de `src/app` quedan delgadas.
2. **Notas en SQLite.** Un adaptador `createSqliteNotesRepository` cumple el puerto `NotesRepository` con `expo-sqlite`. Cierras la app y las notas siguen ahí.
3. **Feature de frases.** Una feature `quotes` muestra una frase aleatoria de https://dummyjson.com/quotes/random con TanStack Query y un botón para pedir otra.
4. **Caché persistente.** La última frase se guarda en AsyncStorage con `PersistQueryClientProvider`, así que al abrir la app sin red se ve la frase anterior en lugar de un error.
5. **Formulario validado.** Crear una nota usa react-hook-form y un esquema de zod para título y contenido.

La API que muestra la frase responde con esta forma, que el adaptador traduce al tipo del dominio:

```json
{ "id": 807, "quote": "Inside of a ring or out, ain't nothing wrong with going down.", "author": "Muhammad Ali" }
```

`notesModule.ts` es la raíz de composición de la feature: el único archivo que importa de `infrastructure`. La feature `quotes` no tiene reglas propias, así que no necesita casos de uso: su adaptador devuelve el tipo del dominio y la interfaz lo muestra. No crees capas vacías.

### El adaptador de SQLite

El adaptador abre la base una sola vez y guarda la promesa, para que todas las llamadas usen la misma conexión:

```ts
// src/features/notes/infrastructure/sqliteNotesRepository.ts
import * as SQLite from "expo-sqlite";
import type { NotesRepository } from "../application/notesService";
import type { Note } from "../domain/note";

type NoteRow = { id: string; title: string; body: string; created_at: string };

export function createSqliteNotesRepository(databaseName: string): NotesRepository {
  const dbPromise = SQLite.openDatabaseAsync(databaseName).then(async (db) => {
    await db.execAsync(
      "CREATE TABLE IF NOT EXISTS notes (id TEXT PRIMARY KEY NOT NULL, title TEXT NOT NULL, body TEXT NOT NULL, created_at TEXT NOT NULL);",
    );
    return db;
  });

  return {
    async list(): Promise<Note[]> {
      const db = await dbPromise;
      const rows = await db.getAllAsync<NoteRow>("SELECT * FROM notes ORDER BY created_at DESC");
      return rows.map((r) => ({ id: r.id, title: r.title, body: r.body, createdAt: r.created_at }));
    },
    async save(note) {
      const db = await dbPromise;
      await db.runAsync(
        "INSERT OR REPLACE INTO notes (id, title, body, created_at) VALUES (?, ?, ?, ?)",
        note.id,
        note.title,
        note.body,
        note.createdAt,
      );
    },
    async remove(id) {
      const db = await dbPromise;
      await db.runAsync("DELETE FROM notes WHERE id = ?", id);
    },
  };
}
```

El adaptador traduce entre `created_at` (el nombre de la columna) y `createdAt` (el nombre del dominio). Esa traducción es justo el trabajo de un adaptador.

### La caché persistente de frases

TanStack Query guarda su caché en memoria. Para que sobreviva al cierre de la app, se envuelve el cliente con `PersistQueryClientProvider` y un persister de AsyncStorage. Documentación: https://tanstack.com/query/latest/docs/framework/react/plugins/persistQueryClient

```bash
npx expo install @tanstack/react-query @tanstack/react-query-persist-client @tanstack/query-async-storage-persister @react-native-async-storage/async-storage
```

```tsx
// src/app/_layout.tsx
import AsyncStorage from "@react-native-async-storage/async-storage";
import { createAsyncStoragePersister } from "@tanstack/query-async-storage-persister";
import { QueryClient } from "@tanstack/react-query";
import { PersistQueryClientProvider } from "@tanstack/react-query-persist-client";
import { Stack } from "expo-router";

const queryClient = new QueryClient({
  defaultOptions: { queries: { gcTime: 1000 * 60 * 60 * 24 } },
});

const persister = createAsyncStoragePersister({ storage: AsyncStorage });

export default function RootLayout() {
  return (
    <PersistQueryClientProvider client={queryClient} persistOptions={{ persister }}>
      <Stack />
    </PersistQueryClientProvider>
  );
}
```

`gcTime` sube a 24 horas porque la documentación pide que sea al menos igual a `maxAge`, el tiempo máximo que se conserva la caché persistida (24 horas por defecto). Con los 5 minutos por defecto, una consulta que ningún componente usa durante 5 minutos se elimina de la memoria y también del almacenamiento, y la frase guardada desaparece antes de tiempo.

### Qué significa terminado

El proyecto está terminado cuando:

- Creas tres notas, cierras la app por completo, la vuelves a abrir y las tres siguen ahí.
- Enviar el formulario con el título vacío muestra el error debajo del campo y no crea nada.
- La frase aparece al abrir, el botón "Otra frase" pide una nueva y, sin red, se ve la última frase guardada.
- `grep -rnE "from \"(react|react-native|expo)" src/features/*/domain` no imprime nada.
- `src/app/index.tsx` y `src/app/new-note.tsx` solo importan y exportan una pantalla; `src/app/_layout.tsx` solo configura proveedores y navegación.

## Errores comunes

**Mover archivos sin mover las dependencias.** Se ve como una carpeta `features/notes/domain` cuyo `note.ts` todavía importa `expo-sqlite` o un componente. Pasa porque reorganizar carpetas se siente como terminar la arquitectura. La estructura promete algo que el código no cumple. Se detecta con el `grep` de la sección "Qué significa terminado". Solución: revisar los imports de cada capa contra la tabla de la lección de screaming architecture.

**Dejar `gcTime` en su valor por defecto con la caché persistente.** Se ve como `PersistQueryClientProvider` configurado pero, a veces, la frase no aparece al abrir sin red. Ocurre porque una consulta sin componentes que la usen se elimina, también del almacenamiento, cuando pasa `gcTime`, que por defecto es de 5 minutos. Se detecta navegando a otra pantalla donde no se muestre la frase durante más de 5 minutos, cerrando la app y abriéndola en modo avión: aparece el error en lugar de la frase. Solución: `gcTime` de 24 horas en el `QueryClient`, igual o mayor que `maxAge`.

**Abrir la base de datos en cada operación.** Se ve como `openDatabaseAsync` dentro de `list` y de `save`. Pasa por copiar el ejemplo de la lección de SQLite dentro de cada método. Cada llamada abre una conexión nueva, lo que es lento y puede provocar errores de base bloqueada. Se detecta porque la lista tarda en aparecer o por errores intermitentes al guardar rápido. Solución: abrir una vez y reutilizar la promesa.
