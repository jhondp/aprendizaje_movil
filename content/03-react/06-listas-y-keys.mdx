## Objetivo

Al terminar esta lección vas a poder renderizar una lista con `.map()`, asignar una `key` estable a cada elemento, y explicar por qué usar el índice del array como key puede provocar bugs cuando la lista cambia.

**Prerrequisitos:** `03-react/05-useref-usememo-usecallback`

## Concepto

Piensa en el guardarropa de un teatro: cuando entregas tu abrigo te dan un ticket numerado, y ese mismo ticket (no la percha donde quedó colgado) es lo que usan para devolverte exactamente tu abrigo al salir, sin importar cuántos abrigos entraron o salieron mientras tanto. La `key` en una lista de React es ese ticket: identifica a cada elemento de forma estable, independiente de en qué posición quede colgado.

### Renderizar una lista con map

```tsx
interface Task {
  id: string;
  title: string;
}

function TaskList({ tasks }: { tasks: Task[] }) {
  return (
    <ul>
      {tasks.map((task) => (
        <li key={task.id}>{task.title}</li>
      ))}
    </ul>
  );
}
```

`.map()` transforma cada elemento del array `tasks` en un elemento JSX `<li>`, produciendo un nuevo array de elementos que React puede renderizar directamente. La prop `key` no es un atributo visual ni llega al DOM como tal: es información privada que React usa para saber, entre un render y el siguiente, cuál elemento de la lista nueva corresponde a cuál elemento de la lista anterior.

Si omites `key` por completo, React renderiza la lista igual, pero muestra una advertencia en la consola: "Warning: Each child in a list should have a unique key prop." Sin esa pista, React solo puede comparar la lista anterior con la nueva por posición, lo cual funciona mientras la lista no cambie de orden ni de tamaño, pero falla apenas insertas, eliminas o reordenas algo.

### Por qué el índice como key es tentador y por qué falla

Cuando no tienes un identificador natural a mano, es tentador escribir `key={index}`, usando la posición que te da `.map((task, index) => ...)`. Mientras la lista solo se agregue al final y nunca se reordene ni se elimine nada del medio, el índice coincide siempre con la misma posición y no causa problemas visibles. El problema aparece cuando eliminas o insertas un elemento que no está al final: la posición 0 sigue siendo la posición 0, pero ahora corresponde a un dato distinto. Si algún componente de esa lista guarda estado propio (con `useState` o `useRef`) en lugar de derivar todo de sus props, React reutiliza esa instancia y su estado interno para la posición, no para el dato original, y el estado termina "pegado" al elemento equivocado.

```tsx
function TaskRow({ title }: { title: string }) {
  const [expanded, setExpanded] = useState(false);
  return (
    <li>
      <button onClick={() => setExpanded(!expanded)}>
        {title} {expanded ? "▲" : "▼"}
      </button>
      {expanded && <p>Detalles de "{title}"</p>}
    </li>
  );
}
```

Si esta fila se renderiza con `key={index}` dentro de una lista donde puedes eliminar el primer elemento, y tenías expandida la fila en la posición 0, después de eliminar ese elemento la posición 0 pasa a mostrar el siguiente título, pero React reutiliza la misma instancia de `TaskRow` (porque para React, "posición 0" no cambió), así que sigue expandida, ahora mostrando los detalles del elemento equivocado. Con `key={task.id}`, React sabe que ese `id` concreto desapareció, destruye esa instancia junto con su estado, y las demás instancias conservan su propio estado porque sus keys no cambiaron.

### Qué hace una buena key

Una key debe ser:

- **Estable**: el mismo dato produce la misma key en cada render, no algo generado al azar en cada llamada a `.map()` (`key={Math.random()}` rompe la identidad en cada render, que es peor que usar el índice).
- **Única** entre los elementos hermanos de esa lista concreta (no hace falta que sea única en toda la aplicación).
- **Derivada del dato**, típicamente un `id` que ya viene de la base de datos o que generas una sola vez al crear el elemento, nunca de su posición.

Documentación oficial: [react.dev/learn/rendering-lists](https://react.dev/learn/rendering-lists).

## Errores comunes

**No poner ninguna key.** React muestra la advertencia "Each child in a list should have a unique key prop" en la consola. La lista igual se renderiza, pero React pierde la capacidad de identificar elementos de forma confiable entre renders. Se detecta leyendo la consola del navegador.

**Usar el índice como key en una lista que se reordena o elimina elementos del medio.** Como viste en el Concepto, esto puede dejar estado local (como un toggle `expanded`) pegado a la posición equivocada después de eliminar o insertar un elemento. Se detecta interactuando con la lista: expande una fila, elimina un elemento anterior, y observa si el estado expandido "salta" a un contenido distinto del que tenías expandido.

**Generar la key con `Math.random()` o `Date.now()` dentro del `.map()`.** Esto produce una key distinta en cada render, incluso si el dato no cambió, lo que le hace creer a React que todos los elementos son nuevos en cada render: destruye y vuelve a crear cada instancia, perdiendo cualquier estado local y perjudicando el rendimiento. Se detecta porque el estado local de cualquier fila se resetea con cada render del padre, no solo cuando el dato cambia de verdad.
