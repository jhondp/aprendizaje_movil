## Objetivo

Al terminar esta lección vas a haber construido un tablero de tareas web en React y TypeScript, con tres columnas, un formulario validado para agregar tareas, botones para moverlas entre columnas, un filtro por texto, el estado elevado a un componente contenedor y al menos un custom hook.

**Prerrequisitos:** `03-react/10-formularios`

## Concepto

Este proyecto retoma la app de consola que migraste a TypeScript en [`02-typescript/08-proyecto-migrar-a-ts`](/etapa/02-typescript/08-proyecto-migrar-a-ts): la misma idea de gestionar tareas con un `interface Task` y un `type` para su estado, pero ahora con una interfaz visual en el navegador en lugar de una lista impresa en la terminal. Cada pieza de este tablero ya la construiste por separado en las lecciones anteriores; este proyecto las combina en una sola aplicación.

### Qué vas a construir

Un tablero con tres columnas fijas — "Por hacer", "En progreso" y "Hecha" — donde cada tarea es una tarjeta que puede moverse de una columna a otra con un botón, en lugar de arrastrarse con el mouse. Un formulario en la parte superior agrega tareas nuevas directamente a "Por hacer", validando que el título tenga al menos tres caracteres. Un campo de texto filtra las tareas visibles por su título, en las tres columnas a la vez, sin perder las tareas que no coinciden con el filtro (siguen existiendo, solo no se muestran).

### Cómo se conectan las piezas que ya conoces

- **El modelo de datos** es una `interface Task` con `id`, `title` y `status` (`"todo" | "doing" | "done"`), el mismo tipo de unión literal que usaste en la etapa de TypeScript.
- **El estado vive en un custom hook**, `useBoard()`, que encapsula el array de tareas, el texto del filtro, y las funciones `addTask` y `moveTask`. Es la misma técnica de la lección "Custom hooks": una función que empieza con `use` y que agrupa varios hooks (`useState`, `useRef` para generar ids) detrás de una API simple.
- **Un componente contenedor**, `BoardContainer`, llama a `useBoard()` y le pasa los datos y las funciones a componentes presentational que no tienen estado propio de negocio: `TaskForm`, `Board` y `Column`. Es la separación de la lección "Composición y container/presentational".
- **Las listas de tareas dentro de cada columna** se renderizan con `.map()` y `key={task.id}`, nunca con el índice, siguiendo la lección "Listas y keys": si movieras una tarea de columna, el índice dentro de cada columna cambiaría, pero el `id` de la tarea no.
- **El formulario de agregar tarea** reutiliza el patrón de `onSubmit`, `preventDefault` y validación de la lección "Formularios".

Documentación oficial de referencia para todo el proyecto: [react.dev/learn/thinking-in-react](https://react.dev/learn/thinking-in-react).

## Práctica

El siguiente Sandpack contiene el tablero completo y funcional. Agrega un par de tareas, muévelas entre columnas con los botones, y escribe en el campo de filtro para ver cómo se ocultan (sin eliminarse) las tareas que no coinciden.

```tsx
type Status = "todo" | "doing" | "done";

interface Task {
  id: string;
  title: string;
  status: Status;
}

const STATUS_ORDER: Status[] = ["todo", "doing", "done"];
const STATUS_LABELS: Record<Status, string> = {
  todo: "Por hacer",
  doing: "En progreso",
  done: "Hecha",
};

function useBoard() {
  const [tasks, setTasks] = useState<Task[]>([
    { id: "t1", title: "Diseñar el tablero", status: "done" },
    { id: "t2", title: "Escribir el formulario", status: "doing" },
    { id: "t3", title: "Conectar el filtro", status: "todo" },
  ]);
  const [query, setQuery] = useState("");
  const nextId = useRef(4);

  function addTask(title: string) {
    setTasks((previous) => [...previous, { id: `t${nextId.current++}`, title, status: "todo" }]);
  }

  function moveTask(id: string, status: Status) {
    setTasks((previous) => previous.map((task) => (task.id === id ? { ...task, status } : task)));
  }

  const visibleTasks = tasks.filter((task) =>
    task.title.toLowerCase().includes(query.toLowerCase()),
  );

  return { tasks: visibleTasks, query, setQuery, addTask, moveTask };
}
```

  const [title, setTitle] = useState("");
  const [error, setError] = useState<string | null>(null);

  function handleSubmit(event: React.FormEvent<HTMLFormElement>) {
    event.preventDefault();
    const trimmed = title.trim();
    if (trimmed.length < 3) {
      setError("El título debe tener al menos 3 caracteres.");
      return;
    }
    setError(null);
    onAdd(trimmed);
    setTitle("");
  }

      <input value={title} onChange={(e) => setTitle(e.target.value)} placeholder="Nueva tarea" />
      <button type="submit">Agregar</button>
      {error && <p role="alert" style={{ color: "crimson" }}>{error}</p>}
    </form>
  );
}

function Column({
  status,
  tasks,
  onMove,
}: {
  status: Status;
  tasks: Task[];
  onMove: (id: string, status: Status) => void;
}) {
  return (
    <div style={{ flex: 1, border: "1px solid #ccc", padding: 8, minWidth: 160 }}>
      <h3>{STATUS_LABELS[status]}</h3>
      <ul style={{ listStyle: "none", padding: 0 }}>
        {tasks.map((task) => (
          <li key={task.id} style={{ marginBottom: 8, borderBottom: "1px solid #eee" }}>
            <p>{task.title}</p>
            <div>
              {STATUS_ORDER.filter((target) => target !== status).map((target) => (
                <button key={target} onClick={() => onMove(task.id, target)}>
                  → {STATUS_LABELS[target]}
                </button>
              ))}
            </div>
          </li>
        ))}
      </ul>
    </div>
  );
}

function Board({ tasks, onMove }: { tasks: Task[]; onMove: (id: string, status: Status) => void }) {
  return (
    <div style={{ display: "flex", gap: 12 }}>
      {STATUS_ORDER.map((status) => (
        <Column
          key={status}
          status={status}
          tasks={tasks.filter((task) => task.status === status)}
          onMove={onMove}
        />
      ))}
    </div>
  );
}

function BoardContainer() {
  const { tasks, query, setQuery, addTask, moveTask } = useBoard();
  return (
    <div>
      <TaskForm onAdd={addTask} />
      <input
        value={query}
        onChange={(e) => setQuery(e.target.value)}
        placeholder="Filtrar por texto"
        style={{ margin: "8px 0" }}
      />
      <Board tasks={tasks} onMove={moveTask} />
    </div>
  );
}

export default function App() {
  return <BoardContainer />;
}`,
  }}

## Errores comunes

**Guardar el resultado filtrado como el nuevo estado en lugar de derivarlo en cada render.** Si al escribir en el campo de filtro reemplazaras `tasks` con el array ya filtrado (en vez de mantener `tasks` completo y calcular `visibleTasks` aparte, como en `useBoard`), las tareas que no coinciden con el filtro se perderían para siempre, no solo se ocultarían. Se detecta borrando el texto del filtro: si las tareas que "desaparecieron" no vuelven a aparecer, el filtro está mutando el estado real en lugar de derivar una vista.

**Mover una tarea "adivinando" su posición en el array en lugar de identificarla por `id`.** Si `moveTask` recibiera un índice de columna en lugar del `id` de la tarea, mover una tarea en una columna filtrada movería la tarea equivocada, porque el índice visible (después de filtrar) no coincide con la posición real en el array completo. Se detecta escribiendo algo en el filtro y moviendo una tarea visible: si se mueve otra tarea distinta a la esperada, la función está usando la posición en lugar del `id`.

**Repetir la lógica de agregar o mover tareas en cada componente en lugar de centralizarla en `useBoard`.** Si `TaskForm` o `Column` manipularan el array de tareas directamente en lugar de llamar a `addTask` o `onMove` recibidos por props, tendrías la misma lógica duplicada en varios lugares y un bug en uno no se corregiría en el otro. Se detecta revisando si más de un componente contiene su propia copia de `setTasks` para la misma lista.
