## Objetivo

Al terminar esta lección vas a poder construir un formulario controlado con `<form>`, manejar su envío con `onSubmit`, y validar un campo mostrando un mensaje de error antes de aceptar los datos.

**Prerrequisitos:** `03-react/09-context`

## Concepto

Piensa en un formulario de papel que entregas en una ventanilla: la persona que lo recibe revisa que esté completo antes de aceptarlo, y si falta algo, te lo devuelve señalando exactamente qué corregir, en lugar de archivarlo incompleto. Un formulario en React funciona igual: antes de aceptar los datos (por ejemplo, antes de agregar una tarea a una lista), revisas que cumplan una condición y, si no la cumplen, se lo indicas a quien lo llenó en lugar de procesarlo a medias.

### Recordando el input controlado

En la lección "State y eventos" ya viste el patrón base: un input cuyo `value` viene del estado y cuyo `onChange` actualiza ese estado.

```tsx
function TaskForm() {
  const [title, setTitle] = useState("");
  return <input value={title} onChange={(event) => setTitle(event.target.value)} />;
}
```

Un formulario completo agrupa uno o más de estos inputs controlados dentro de un elemento `<form>`, y agrega un manejador para el momento en que el formulario se envía.

### Manejar el envío con onSubmit

```tsx
function TaskForm({ onAdd }: { onAdd: (title: string) => void }) {
  const [title, setTitle] = useState("");

  function handleSubmit(event: React.FormEvent<HTMLFormElement>) {
    event.preventDefault();
    onAdd(title);
    setTitle("");
  }

  return (
    <form onSubmit={handleSubmit}>
      <input value={title} onChange={(event) => setTitle(event.target.value)} />
      <button type="submit">Agregar</button>
    </form>
  );
}
```

`event.preventDefault()` es la línea más importante de este bloque: el comportamiento por defecto de un `<form>` en el navegador es recargar la página y enviar los datos como si fuera un formulario clásico de HTML, sin JavaScript. Eso destruiría todo el estado de tu aplicación de React en ese mismo instante. Al llamar a `preventDefault()`, le dices al navegador "yo me encargo de este envío", y el control queda enteramente en tu código.

### Validar antes de aceptar

Agregar validación significa revisar los datos antes de llamar a la función que los acepta, y guardar un mensaje de error en estado cuando no son válidos:

```tsx
function TaskForm({ onAdd }: { onAdd: (title: string) => void }) {
  const [title, setTitle] = useState("");
  const [error, setError] = useState<string | null>(null);

  function handleSubmit(event: React.FormEvent<HTMLFormElement>) {
    event.preventDefault();
    const trimmed = title.trim();
    if (trimmed.length < 3) {
      setError("El título debe tener al menos 3 caracteres.");
      return;
    }
    setError(null);
    onAdd(trimmed);
    setTitle("");
  }

  return (
    <form onSubmit={handleSubmit}>
      <input value={title} onChange={(event) => setTitle(event.target.value)} placeholder="Nueva tarea" />
      <button type="submit">Agregar</button>
      {error && <p role="alert">{error}</p>}
    </form>
  );
}
```

Tres decisiones importan aquí: la validación se hace dentro del propio `handleSubmit`, antes de llamar a `onAdd`, así que datos inválidos nunca llegan a quien procesa el formulario; el mensaje de error vive en su propio estado (`error`), separado del valor del campo (`title`), porque son dos cosas distintas: una es el dato, la otra es la retroalimentación sobre ese dato; y `setError(null)` limpia un error anterior en cuanto el envío es válido, para que el mensaje no quede pegado en pantalla después de corregirlo.

### Cuándo validar: en cada tecla o al enviar

Validar en cada tecla (dentro de `onChange`) da retroalimentación inmediata, pero puede resultar molesto si marca un error mientras el usuario todavía está escribiendo la primera letra. Validar solo en `onSubmit`, como en el ejemplo, evita ese ruido, a costa de que el usuario no se entera del problema hasta que intenta enviar. Una alternativa común es validar en el evento `onBlur` (cuando el campo pierde el foco), un punto intermedio que no cubre esta lección pero que sigue el mismo principio: guardar el resultado de la validación en estado y mostrarlo condicionalmente en el JSX.

Documentación oficial: [react.dev/reference/react-dom/components/input](https://react.dev/reference/react-dom/components/input) y [react.dev/reference/react-dom/components/form](https://react.dev/reference/react-dom/components/form).

## Práctica

```tsx
    event.preventDefault();
    const trimmed = title.trim();

      setError("El título debe tener al menos 3 caracteres.");
      return;

    setError(null);
    onAdd(trimmed);
    setTitle("");
  }

  return (
    <form onSubmit={handleSubmit}>
      <input value={title} onChange={(event) => setTitle(event.target.value)} placeholder="Nueva tarea" />
      <button type="submit">Agregar</button>
      {error && <p role="alert">{error}</p>}
    </form>
  );
}
```

## Errores comunes

**Olvidar `event.preventDefault()`.** Sin esa línea, al enviar el formulario el navegador recarga la página completa como si fuera un formulario clásico de HTML, perdiendo todo el estado de React en el proceso. Se detecta porque la página "parpadea" y se reinicia al enviar, en lugar de actualizarse solo con JavaScript.

**Dejar el input sin `value`, o alternar entre un string y `undefined`.** Si el input no recibe `value` en absoluto, el navegador lo maneja de forma no controlada (el DOM guarda el valor, no React); si alterna entre un `value` definido y `undefined` según alguna condición, React muestra la advertencia "A component is changing an uncontrolled input to be controlled". Se detecta por ese mensaje exacto en la consola; la solución es inicializar el estado siempre con un string, nunca con `undefined`.

**Mostrar el error de validación desde la primera tecla, antes de que el usuario termine de escribir.** Si validas dentro del `onChange` y muestras el error de inmediato, el usuario ve un mensaje de "muy corto" mientras todavía está escribiendo la primera letra, lo cual se siente como un regaño prematuro. Se detecta pidiendo a alguien que use el formulario y observando si el mensaje aparece y desaparece de forma molesta mientras escribe; la solución más simple es validar en `onSubmit`, como en el ejemplo.
