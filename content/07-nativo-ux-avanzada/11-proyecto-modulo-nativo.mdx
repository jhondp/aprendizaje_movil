## Objetivo

Al terminar este proyecto tu app de notas podrá adjuntar fotos tomadas con la cámara, animará cada nota nueva con un resorte, mostrará la lista con `FlashList`, será usable con un lector de pantalla y estará disponible en español e inglés.

**Prerrequisitos:** `07-nativo-ux-avanzada/10-performance`

## Concepto

Hasta ahora la app de notas era correcta: guardaba datos, tenía arquitectura por capas y un pipeline que la protegía. Este proyecto la convierte en una app que se siente nativa. Es como pasar de una casa con planos aprobados y paredes firmes a una casa en la que se vive bien: ventanas que dejan entrar luz (la cámara), puertas que se abren con suavidad (las animaciones), rampas para quien las necesita (la accesibilidad) y carteles en dos idiomas para las visitas.

Documentación de referencia: https://docs.expo.dev/versions/latest/sdk/camera/, https://docs.expo.dev/versions/latest/sdk/filesystem/, https://shopify.github.io/flash-list/ y https://reactnative.dev/docs/accessibility

### Punto de partida

Trabajas sobre el repositorio que terminaste en [el proyecto de la etapa 6](/etapa/06-calidad-ci/07-proyecto-pipeline-verde): la app de notas con carpetas por feature en `src/features/notes/`, el puerto `NotesRepository` con su adaptador de SQLite, pruebas con Jest y un workflow de CI en verde. Crea una rama nueva para este proyecto y abre un pull request al terminar: el pipeline debe seguir en verde.

La cámara y los textos de propósito necesitan una development build o, como mínimo, Expo Go en un teléfono físico. El reproductor web no sirve para este proyecto.

### Qué vas a construir

**1. Foto adjunta con la cámara.** Cada nota puede tener una foto.

- Instala `expo-camera` y `expo-file-system` con `npx expo install`.
- Crea la ruta `src/app/note/[id]/camera.tsx` con `CameraView` y `useCameraPermissions`, con los tres estados: cargando, sin permiso (con explicación y botón) y con permiso.
- Al tomar la foto, cópiala de la caché a un directorio permanente antes de guardar su ruta:

```tsx
import { Directory, File, Paths } from "expo-file-system";

export async function persistPhoto(cacheUri: string): Promise<string> {
  const photos = new Directory(Paths.document, "photos");
  if (!photos.exists) photos.create();

  const source = new File(cacheUri);
  const target = new File(photos, Date.now() + ".jpg");
  await source.copy(target);
  return target.uri;
}
```

- Agrega a la entidad `Note` un campo opcional `photoUri` y una migración de SQLite que añada la columna `photo_uri`. El dominio no sabe nada de la cámara: solo guarda una ruta.
- Configura el plugin de `expo-camera` en `app.json` con un texto de propósito que explique para qué sirve la cámara y desactiva el micrófono.

**2. Animación con resorte al agregar una nota.** La nota recién creada entra en la lista con `withSpring`. Como `FlashList` recicla filas, no te fíes de "al montarse": anima cuando cambia el id de la fila y solo si es la nota nueva.

```tsx
function NoteRow({ note, isNew }: { note: Note; isNew: boolean }) {
  const translateY = useSharedValue(0);

  useEffect(() => {
    if (!isNew) return;
    translateY.value = -30;
    translateY.value = withSpring(0, { damping: 9 });
  }, [note.id, isNew, translateY]);

  const style = useAnimatedStyle(() => ({ transform: [{ translateY: translateY.value }] }));
  return <Animated.View style={style}>{/* row content */}</Animated.View>;
}
```

**3. FlashList.** Sustituye el `FlatList` de la pantalla principal por `FlashList`. No uses `estimatedItemSize`. Si alguna fila guarda estado local, usa `useRecyclingState`. Envuelve la fila en `memo` y pasa los manejadores con `useCallback` si el Profiler muestra renders de más.

**4. Accesibilidad.** Todos los elementos interactivos tienen `accessibilityRole` y `accessibilityLabel`. En particular:

- El botón de cámara dice "Adjuntar foto", no "Cámara".
- La miniatura de la foto tiene una etiqueta como "Foto adjunta a Lista de compras".
- Cada fila se lee como una sola parada: título, fecha y si tiene foto.
- Si tu lista tiene "deslizar para borrar", ofrece también una acción de accesibilidad o un botón visible.
- Revisa la app con la letra del sistema al máximo.

**5. Español e inglés.** Todos los textos visibles y las etiquetas de accesibilidad salen de `i18n-js`:

```text
src/
  i18n/
    index.ts      # creates the I18n instance and reads getLocales()
    es.json
    en.json
```

El idioma inicial es el del dispositivo, con inglés como respaldo. Las fechas de las notas se formatean con `Intl.DateTimeFormat` y el `languageTag` del usuario. Los plurales ("1 nota", "3 notas") usan claves `one` y `other`.

  platform="ios"
  sdkVersion="55.0.0"
  dependencies={{ '@shopify/flash-list': '2.0.2', 'react-native-reanimated': '4.2.1', 'react-native-worklets': '0.7.4', 'i18n-js': '4.5.3' }}

import { Button, StyleSheet, Text, View } from "react-native";
import { FlashList } from "@shopify/flash-list";
import Animated, { useAnimatedStyle, useSharedValue, withSpring } from "react-native-reanimated";
import { I18n } from "i18n-js";

const i18n = new I18n({
  es: { add: "Agregar nota", note: "Nota %{n}", switch: "English", count: { one: "1 nota", other: "%{count} notas" } },
  en: { add: "Add note", note: "Note %{n}", switch: "Español", count: { one: "1 note", other: "%{count} notes" } }
});

type Note = { id: string; n: number };

function NoteRow({ note, isNew }: { note: Note; isNew: boolean }) {
  const translateY = useSharedValue(0);

  useEffect(() => {
    if (!isNew) return;
    translateY.value = -30;
    translateY.value = withSpring(0, { damping: 9 });
  }, [note.id, isNew, translateY]);

  const style = useAnimatedStyle(() => ({ transform: [{ translateY: translateY.value }] }));
  const title = i18n.t("note", { n: note.n });

  return (
    <Animated.View style={[styles.row, style]} accessible accessibilityLabel={title}>
      <Text style={styles.title}>{title}</Text>
    </Animated.View>
  );
}

export default function App() {
  const [locale, setLocale] = useState("es");
  const [notes, setNotes] = useState<Note[]>([]);
  i18n.locale = locale;

  function add() {
    setNotes((current) => [{ id: String(Date.now()), n: current.length + 1 }, ...current]);
  }

  return (
    <View style={styles.container}>
      <Text accessibilityRole="header" style={styles.header}>
        {i18n.t("count", { count: notes.length })}
      </Text>
      <View style={styles.bar}>
        <Button title={i18n.t("add")} onPress={add} />
        <Button title={i18n.t("switch")} onPress={() => setLocale(locale === "es" ? "en" : "es")} />
      </View>
      <FlashList
        data={notes}
        extraData={locale}
        keyExtractor={(note) => note.id}
        renderItem={({ item, index }) => <NoteRow note={item} isNew={index === 0} />}
      />
    </View>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, paddingTop: 60, paddingHorizontal: 16, gap: 12 },
  header: { fontSize: 22, fontWeight: "700" },
  bar: { flexDirection: "row", justifyContent: "space-between" },
  row: { padding: 16, marginBottom: 8, borderRadius: 12, backgroundColor: "#efe6da" },
  title: { fontSize: 16 }
});`}

## Errores comunes

**Guardar en la base de datos la ruta de la caché.** Las fotos aparecen durante unos días y luego las notas muestran imágenes rotas. Ocurre porque se guarda directamente `photo.uri` de `takePictureAsync`. Se detecta porque la ruta guardada contiene `Cache`. Solución: copia el archivo con `persistPhoto` y guarda la ruta nueva.

**Animar solo al montar con FlashList.** La primera nota se anima, pero las siguientes aparecen sin animación o se anima una fila equivocada. Ocurre porque FlashList recicla filas y el efecto de montaje no vuelve a ejecutarse. Se detecta al agregar varias notas seguidas con la lista llena. Solución: incluye `note.id` en las dependencias del efecto y anima solo la nota nueva.

**Traducir la pantalla pero no las etiquetas de accesibilidad.** En inglés, VoiceOver sigue leyendo "Adjuntar foto". Ocurre porque las etiquetas se escribieron como texto fijo en las props. Se detecta recorriendo la app con el lector en inglés. Solución: las etiquetas también salen de `i18n.t`.

**Romper el pipeline con módulos nativos en las pruebas.** Jest falla con errores de módulos nativos no encontrados al importar `expo-camera` o `expo-file-system`. Ocurre porque las pruebas no corren en un teléfono. Se detecta en la ejecución de CI. Solución: simula esos módulos con `jest.mock` y mantén la lógica en funciones que reciben dependencias.
