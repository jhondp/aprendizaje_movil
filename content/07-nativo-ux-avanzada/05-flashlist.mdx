## Objetivo

Al terminar esta lección podrás renderizar una lista larga con `FlashList`, explicar cómo recicla las filas y usar `getItemType` cuando la lista mezcla filas de distinto tipo.

**Prerrequisitos:** `07-nativo-ux-avanzada/04-gestos`

## Concepto

En la etapa 4 usaste `FlatList` para mostrar notas. `FlatList` es virtualizada: solo monta las filas que están cerca de la pantalla y desmonta las que se alejan. Funciona bien con decenas o cientos de elementos, pero cuando el usuario hace scroll rápido por miles de notas, montar y desmontar componentes sin parar cuesta tiempo, y aparecen huecos en blanco antes de que las filas lleguen.

`FlashList`, de Shopify, cambia la estrategia: en lugar de destruir una fila que sale de la pantalla, la **recicla**. Toma ese mismo componente ya montado y le pasa los datos de la fila que va a entrar.

La analogía: piensa en los platos de un restaurante. `FlatList` tira cada plato a la basura cuando el cliente termina y fabrica uno nuevo para el siguiente. `FlashList` lava el plato y lo vuelve a servir con otra comida. Fabricar platos es caro; lavarlos es barato. Por eso el resultado es un scroll más fluido con menos trabajo del hilo de JavaScript.

Documentación oficial: https://shopify.github.io/flash-list/ y https://shopify.github.io/flash-list/docs/v2-changes

### Instalar y usar

```bash
npx expo install @shopify/flash-list
```

La API imita a `FlatList`, así que el cambio suele ser de una línea:

```tsx
import { FlashList } from "@shopify/flash-list";

type Note = { id: string; title: string };

export function NoteList({ notes }: { notes: Note[] }) {
  return (
    <FlashList
      data={notes}
      keyExtractor={(note) => note.id}
      renderItem={({ item }) => <NoteRow note={item} />}
    />
  );
}
```

`data`, `renderItem`, `keyExtractor`, `ListEmptyComponent`, `onEndReached` y `ItemSeparatorComponent` funcionan igual que en `FlatList`.

### `estimatedItemSize` ya no existe en v2

Si lees artículos sobre FlashList, casi todos te piden pasar `estimatedItemSize`, un número con la altura aproximada de cada fila. Eso era obligatorio en FlashList v1. Expo SDK 55 instala FlashList v2, que mide las filas por sí sola gracias a la New Architecture y **ya no lee esa prop**. Si la escribes, no pasa nada útil: solo es ruido que confunde a quien lee el código.

<Callout kind="tip">
  FlashList v2 solo funciona con la New Architecture, que es la opción por defecto en los proyectos Expo actuales. Si algún día trabajas en un proyecto antiguo con la arquitectura clásica, tendrás que usar FlashList v1 y entonces sí necesitarás `estimatedItemSize`.
</Callout>

### Tipos de fila con `getItemType`

El reciclaje funciona mejor cuando las filas que se intercambian se parecen. Si tu lista mezcla encabezados de fecha y notas, reciclar un encabezado para convertirlo en nota obliga a React a reconstruir casi todo. `getItemType` le dice a FlashList qué filas son del mismo tipo, y solo recicla entre filas del mismo grupo:

```tsx
type Row = { kind: "header"; id: string; label: string } | { kind: "note"; id: string; title: string };

<FlashList
  data={rows}
  keyExtractor={(row) => row.id}
  getItemType={(row) => row.kind}
  renderItem={({ item }) =>
    item.kind === "header" ? <DateHeader label={item.label} /> : <NoteRow title={item.title} />
  }
/>;
```

Es el mismo principio de los platos: el restaurante lava los platos hondos para servir sopa y los planos para servir carne. No sirve sopa en un plato plano.

### Cuidado con el estado dentro de una fila

Como la fila se reutiliza, un `useState` dentro de `NoteRow` **sobrevive** cuando la fila pasa a mostrar otra nota. Si una fila tenía `expanded = true` y se recicla, la nota siguiente aparece expandida sin que nadie la haya tocado. Tienes dos salidas:

- Guardar ese estado fuera de la fila, por ejemplo en un objeto indexado por `id` en el componente padre o en tu store.
- Usar `useRecyclingState` de FlashList, que se reinicia cuando cambian sus dependencias:

```tsx
import { useRecyclingState } from "@shopify/flash-list";

function NoteRow({ note }: { note: Note }) {
  const [expanded, setExpanded] = useRecyclingState(false, [note.id]);
  // expanded goes back to false whenever this row shows a different note.
}
```

Por el mismo motivo, no pongas una prop `key` en el componente raíz de la fila: obligaría a React a desmontarlo y perderías el reciclaje. El `keyExtractor` de la lista es suficiente.

### Cuándo usar cada una

- Lista corta (menos de unas cien filas) y simple: `FlatList` está bien y no añade dependencias.
- Lista larga, filas con imágenes o scroll muy rápido: `FlashList`.
- Pocos elementos que siempre caben en pantalla: ni siquiera necesitas una lista virtualizada; un `ScrollView` basta.

Mide antes de cambiar. En la lección de performance verás cómo detectar si la lista es realmente el cuello de botella.

## Práctica

El Snack genera 5000 notas agrupadas por día, con encabezados y filas de nota. Haz scroll rápido. Después cambia `getItemType` por una función que devuelva siempre `"row"` y observa si notas diferencia en tu teléfono.

<Snack
  platform="ios"
  sdkVersion="55.0.0"
  dependencies={{ '@shopify/flash-list': '2.0.2' }}
  code={`import { StyleSheet, Text, View } from "react-native";
import { FlashList } from "@shopify/flash-list";

type Row =
  | { kind: "header"; id: string; label: string }
  | { kind: "note"; id: string; title: string };

const ROWS: Row[] = [];
for (let i = 0; i < 5000; i++) {
  if (i % 20 === 0) {
    ROWS.push({ kind: "header", id: "h" + i, label: "Día " + (i / 20 + 1) });
  }
  ROWS.push({ kind: "note", id: "n" + i, title: "Nota número " + (i + 1) });
}

export default function App() {
  return (
    <View style={styles.container}>
      <FlashList
        data={ROWS}
        keyExtractor={(row) => row.id}
        getItemType={(row) => row.kind}
        renderItem={({ item }) =>
          item.kind === "header" ? (
            <Text style={styles.header}>{item.label}</Text>
          ) : (
            <View style={styles.note}>
              <Text style={styles.title}>{item.title}</Text>
            </View>
          )
        }
      />
    </View>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, paddingTop: 48 },
  header: { fontSize: 14, fontWeight: "700", padding: 12, backgroundColor: "#efe6da" },
  note: { padding: 16, borderBottomWidth: StyleSheet.hairlineWidth, borderColor: "#cccccc" },
  title: { fontSize: 16 }
});`}
/>

## Errores comunes

**Copiar `estimatedItemSize` de tutoriales de v1.** Se ve como una prop numérica que nadie sabe de dónde salió y que no cambia nada. Ocurre porque la mayoría de artículos se escribieron para FlashList v1. Se detecta revisando la versión en `package.json`: si es 2.x, la prop no se usa. Solución: bórrala.

**Estado local que "salta" entre filas.** Una fila aparece marcada, expandida o con un texto escrito que pertenecía a otra nota. Ocurre porque FlashList reutiliza el componente y su `useState` sobrevive al reciclaje. Se detecta al hacer scroll después de cambiar el estado de una fila. Solución: mueve el estado al padre indexado por `id` o usa `useRecyclingState`.

**Poner `key` en la raíz de la fila.** El scroll se siente igual o peor que con `FlatList`. Ocurre porque una `key` distinta en cada fila obliga a React a desmontar y montar el componente, justo lo que el reciclaje evita. Se detecta buscando `key=` dentro de `renderItem`. Solución: quítala y deja que `keyExtractor` identifique las filas.
