## Objetivo

Al terminar esta lección podrás configurar un `scheme` en `app.json`, abrir una nota concreta desde un enlace, leer sus parámetros con `useLocalSearchParams` y explicar qué añade un universal link.

**Prerrequisitos:** `07-nativo-ux-avanzada/07-i18n`

## Concepto

Un **deep link** es un enlace que abre tu app directamente en una pantalla concreta, no en la de inicio. "Abre la nota 42" desde una notificación, un correo o un mensaje de chat es un deep link.

La analogía: una dirección postal completa. Decir "voy al edificio Saber" te deja en la puerta; decir "edificio Saber, piso 3, oficina 42" te lleva al escritorio exacto. El `scheme` es el nombre del edificio, la ruta es el piso y la oficina, y los parámetros de consulta (`?from=push`) son la nota adhesiva que dice quién te envió.

Documentación oficial: https://docs.expo.dev/linking/overview/ y https://docs.expo.dev/linking/into-your-app/

### Anatomía de un enlace

```text
saber://note/42?from=push
└─┬─┘   └──┬──┘ └───┬───┘
scheme    ruta   parámetros
```

- El **scheme** (`saber`) identifica a tu app en el sistema. Lo declaras en `app.json`.
- La **ruta** (`note/42`) coincide con un archivo de rutas de Expo Router.
- Los **parámetros de consulta** (`from=push`) son datos extra.

### Declarar el scheme

```json
{
  "expo": {
    "scheme": "saber"
  }
}
```

Al compilar, Expo registra `saber://` en iOS y Android. Como cualquier cambio nativo, necesita una compilación nueva. En Expo Go no puedes usar tu scheme: los enlaces tienen la forma `exp://127.0.0.1:8081/--/note/42`, donde `/--/` separa la dirección del servidor de desarrollo de la ruta de tu app.

### Expo Router hace el trabajo

En la etapa 4 creaste `src/app/note/[id].tsx`. Con Expo Router, cada archivo de rutas ya es un destino de deep link: `saber://note/42` abre esa pantalla sin código adicional. Dentro de la pantalla lees los parámetros con `useLocalSearchParams`, igual que cuando navegabas con `router.push`:

```tsx
import { useLocalSearchParams } from "expo-router";
import { Text } from "react-native";

export default function NoteScreen() {
  const { id, from } = useLocalSearchParams<{ id: string; from?: string }>();
  return (
    <Text>
      Nota {id} {from ? `(abierta desde ${from})` : ""}
    </Text>
  );
}
```

Los parámetros de ruta (`[id]`) y los de consulta (`?from=`) llegan en el mismo objeto, siempre como texto. Si `id` debe ser un número, conviértelo y valida que exista: un enlace puede venir de cualquier parte, incluso con datos inventados.

### Crear y leer enlaces con `expo-linking`

Para **generar** un enlace que funcione tanto en Expo Go como en tu compilación, usa `Linking.createURL`, que elige el prefijo correcto:

```tsx
import * as Linking from "expo-linking";

const url = Linking.createURL("note/42", { queryParams: { from: "share" } });
// Expo Go: exp://192.168.1.10:8081/--/note/42?from=share
// Build:   saber://note/42?from=share
```

Si necesitas leer un enlace fuera de Expo Router, `Linking.parse(url)` lo separa en `scheme`, `hostname`, `path` y `queryParams`. Ojo con un detalle: en `saber://note/42`, la parte `note` se interpreta como `hostname` y `42` como `path`, porque así funcionan las URL estándar. Expo Router ya lo tiene en cuenta; si lo haces a mano, combina ambos.

### Probar desde la terminal

No necesitas enviarte correos para probar. `npx uri-scheme` abre un enlace en el simulador o emulador que está corriendo. La práctica muestra los comandos paso a paso.

### Universal links y App Links

Un enlace `saber://` tiene dos problemas: si la app no está instalada, no pasa nada, y cualquier otra app podría registrar el mismo scheme. Los **universal links** (iOS) y **App Links** (Android) usan un dominio `https` que tú controlas:

- `https://saber.app/note/42` abre la app si está instalada y, si no, la página web.
- El sistema verifica que el dominio es tuyo descargando un archivo desde `https://saber.app/.well-known/`: `apple-app-site-association` para iOS y `assetlinks.json` para Android.

```json
{
  "expo": {
    "ios": { "associatedDomains": ["applinks:saber.app"] },
    "android": {
      "intentFilters": [
        {
          "action": "VIEW",
          "autoVerify": true,
          "data": [{ "scheme": "https", "host": "saber.app", "pathPrefix": "/note" }],
          "category": ["BROWSABLE", "DEFAULT"]
        }
      ]
    }
  }
}
```

Necesitas un dominio propio y la configuración de firma de la app, así que esta parte se completa cuando publiques en la etapa 10. Lo importante ahora es la idea: el scheme propio sirve para desarrollo y enlaces internos; los universal links son los que compartes con el mundo.

<Callout kind="warning">
  Trata cada parámetro de un enlace como una entrada del usuario. Un enlace como `saber://note/42?delete=true` no debe borrar nada sin confirmación: cualquiera puede escribir un enlace y enviártelo.
</Callout>

## Errores comunes

**Probar el scheme propio en Expo Go.** `npx uri-scheme open saber://note/42` no hace nada o abre otra app. Ocurre porque Expo Go solo responde a `exp://`; tu scheme existe únicamente en una compilación propia. Se detecta porque el mismo enlace con `exp://127.0.0.1:8081/--/note/42` sí funciona. Solución: usa `Linking.createURL` para generar enlaces y prueba el scheme en una development build.

**Confiar en los parámetros del enlace.** Una pantalla se rompe con `saber://note/abc` o ejecuta acciones con `?delete=true`. Ocurre porque se trata el enlace como si viniera de la propia app. Se detecta probando enlaces con valores inválidos. Solución: valida tipo y existencia, y nunca ejecutes acciones destructivas desde un enlace sin confirmación.

**Buscar la ruta solo en `path`.** Con `saber://note/42`, `path` vale `"42"` y el código no encuentra `note`. Ocurre porque en una URL estándar la primera parte después de `//` es el `hostname`. Se detecta imprimiendo el resultado de `Linking.parse`. Solución: deja que Expo Router resuelva la ruta o combina `hostname` y `path`.
