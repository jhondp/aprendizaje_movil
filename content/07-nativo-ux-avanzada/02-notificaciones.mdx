## Objetivo

Al terminar esta lección podrás programar una notificación local con `expo-notifications`, reaccionar cuando el usuario la toca y describir los pasos del flujo de notificaciones push.

**Prerrequisitos:** `07-nativo-ux-avanzada/01-camara`

## Concepto

Una notificación es un mensaje que aparece fuera de tu app: en la pantalla de bloqueo, en el centro de notificaciones o como un banner encima de otra app. Hay dos tipos y conviene no confundirlos:

- **Local**: la programa tu propia app en el teléfono. "Recuérdame esta nota en una hora" es una notificación local. No necesita servidor ni internet.
- **Push**: la envía un servidor a través de Apple (APNs) o Google (FCM). "Ana compartió una nota contigo" es una notificación push, porque el evento ocurre fuera del teléfono.

La analogía: una notificación local es la alarma que pones en tu propio despertador. Una notificación push es una carta que alguien te envía por correo: necesita tu dirección (el token del dispositivo), una oficina de correos (APNs o FCM) y un remitente (tu servidor).

Documentación oficial: https://docs.expo.dev/versions/latest/sdk/notifications/ y https://docs.expo.dev/push-notifications/overview/

### Pedir permiso

Desde Android 13 y en todas las versiones de iOS, mostrar notificaciones requiere permiso. El patrón es el mismo de las lecciones anteriores:

```tsx
import * as Notifications from "expo-notifications";

const { status } = await Notifications.requestPermissionsAsync();
if (status !== "granted") {
  // Keep the app usable; reminders are optional.
}
```

### Qué hacer cuando la app está abierta

Por defecto, si la notificación llega con la app en primer plano, el sistema no la muestra. Para decidir qué hacer, registra un manejador una sola vez, fuera de los componentes:

```tsx
Notifications.setNotificationHandler({
  handleNotification: async () => ({
    shouldShowBanner: true,
    shouldShowList: true,
    shouldPlaySound: false,
    shouldSetBadge: false,
  }),
});
```

`shouldShowBanner` muestra el aviso flotante; `shouldShowList` la deja en el centro de notificaciones.

### Programar una notificación local

`scheduleNotificationAsync` recibe el contenido y un disparador (`trigger`). El disparador de intervalo de tiempo es el más simple:

```tsx
await Notifications.scheduleNotificationAsync({
  content: {
    title: "Recordatorio",
    body: "Revisa tu nota: lista de compras",
    data: { noteId: "42" },
  },
  trigger: {
    type: Notifications.SchedulableTriggerInputTypes.TIME_INTERVAL,
    seconds: 60,
  },
});
```

Hay otros disparadores: `DATE` (una fecha concreta), `DAILY` y `WEEKLY` (repetidos a una hora). Si pasas `trigger: null`, la notificación se muestra de inmediato.

El campo `data` es tu equipaje de mano: viaja con la notificación y lo lees cuando el usuario la toca. Guarda ahí identificadores, no datos completos.

### Canales en Android

Android agrupa las notificaciones en **canales**, y el usuario puede silenciar cada canal por separado. Crea al menos uno antes de programar:

```tsx
import { Platform } from "react-native";

if (Platform.OS === "android") {
  await Notifications.setNotificationChannelAsync("reminders", {
    name: "Recordatorios",
    importance: Notifications.AndroidImportance.DEFAULT,
  });
}
```

### Responder al toque

Cuando el usuario toca la notificación, tu app se abre y recibes una respuesta con el contenido original. Suscríbete en un efecto y cancela la suscripción al desmontar:

```tsx
useEffect(() => {
  const subscription = Notifications.addNotificationResponseReceivedListener((response) => {
    const noteId = response.notification.request.content.data.noteId;
    // Navigate to the note, for example with router.push.
  });
  return () => subscription.remove();
}, []);
```

### El flujo push

<Callout kind="warning">
  Las notificaciones push necesitan un dispositivo físico y un proyecto de EAS con su `projectId`. En Expo Go para Android no están disponibles desde el SDK 53: necesitas una compilación de desarrollo, que la etapa 10 enseña a crear. Las notificaciones locales sí funcionan en Expo Go.
</Callout>

El flujo tiene cuatro pasos:

1. La app pide permiso.
2. La app obtiene un **token push de Expo**, una dirección única para ese dispositivo e instalación.
3. La app envía ese token a tu servidor, que lo guarda asociado al usuario.
4. Cuando ocurre un evento, el servidor envía un mensaje al servicio push de Expo, que lo entrega a APNs o FCM.

Pasos 1 y 2 en la app:

```tsx
import * as Device from "expo-device";
import Constants from "expo-constants";
import * as Notifications from "expo-notifications";

export async function registerForPushNotifications(): Promise<string | null> {
  if (!Device.isDevice) return null; // Simulators cannot receive push notifications.

  const { status } = await Notifications.requestPermissionsAsync();
  if (status !== "granted") return null;

  const projectId = Constants.expoConfig?.extra?.eas?.projectId ?? Constants.easConfig?.projectId;
  if (!projectId) throw new Error("Missing EAS projectId");

  const token = await Notifications.getExpoPushTokenAsync({ projectId });
  return token.data; // For example: ExponentPushToken[xxxxxxxxxxxxxxxxxxxxxx]
}
```

Paso 4, desde el servidor (o desde tu terminal para probar):

```bash
curl -H "Content-Type: application/json" \
  -X POST https://exp.host/--/api/v2/push/send \
  -d '{"to": "ExponentPushToken[xxxxxxxxxxxxxxxxxxxxxx]", "title": "Nota compartida", "body": "Ana compartió una nota contigo", "data": {"noteId": "42"}}'
```

El paso 3 depende de tu backend; la etapa 8 construye uno. Por ahora basta con saber que el token es un dato del usuario y que puede cambiar: vuelve a registrarlo en cada arranque.

import { Button, Platform, StyleSheet, Text, View } from "react-native";

Notifications.setNotificationHandler({
  handleNotification: async () => ({
    shouldShowBanner: true,

export default function App() {
  const [message, setMessage] = useState("Sin notificaciones programadas");

  useEffect(() => {
    const subscription = Notifications.addNotificationResponseReceivedListener((response) => {
      const data = response.notification.request.content.data;
      setMessage("Abriste la nota " + String(data.noteId));
    });

  async function schedule() {
    const { status } = await Notifications.requestPermissionsAsync();
    if (status !== "granted") {
      setMessage("Permiso rechazado");
      return;
    }
    if (Platform.OS === "android") {
      await Notifications.setNotificationChannelAsync("reminders", {
        name: "Recordatorios",
        importance: Notifications.AndroidImportance.DEFAULT
      });
    }
    await Notifications.scheduleNotificationAsync({
      content: { title: "Recordatorio", body: "Revisa tu lista de compras", data: { noteId: "42" } },
      trigger: { type: Notifications.SchedulableTriggerInputTypes.TIME_INTERVAL, seconds: 5 }
    });
    setMessage("Programada para dentro de 5 segundos");
  }

  return (
    <View style={styles.container}>
      <Text style={styles.text}>{message}</Text>
      <Button title="Programar en 5 segundos" onPress={schedule} />
    </View>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, justifyContent: "center", alignItems: "center", gap: 12, padding: 24 },
  text: { fontSize: 16, textAlign: "center" }
});`}

## Errores comunes

**No registrar `setNotificationHandler`.** La notificación nunca aparece mientras pruebas con la app abierta. Ocurre porque, sin manejador, el sistema no muestra notificaciones en primer plano. Se detecta porque sí aparece cuando bloqueas la pantalla. Solución: registra el manejador una vez, fuera de los componentes.

**Intentar obtener el token push en un simulador o en Expo Go para Android.** `getExpoPushTokenAsync` lanza un error o nunca devuelve. Ocurre porque push necesita un dispositivo físico y, en Android, una compilación de desarrollo. Se detecta con `Device.isDevice` en `false` o con el mensaje de error en la consola. Solución: prueba push en un teléfono con una compilación propia y usa notificaciones locales para el resto.

**Olvidar cancelar la suscripción del listener.** Al tocar una notificación, la acción se ejecuta dos o tres veces. Ocurre porque cada montaje del componente agrega otro listener. Se detecta con logs repetidos por cada toque. Solución: devuelve `() => subscription.remove()` desde el efecto.
