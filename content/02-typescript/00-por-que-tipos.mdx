## Objetivo

Al terminar esta lección vas a poder explicar qué es TypeScript, qué diferencia hay entre un error de tipos y un error en tiempo de ejecución, y por qué este curso muestra los errores de tipos como texto en vez de como salida de consola.

**Prerrequisitos:** `01-javascript/13-proyecto-app-de-tareas`

## Concepto

Piensa en un formulario de aduana. El campo "peso en kilos" espera un número. Si escribes "bastante", el formulario en papel lo acepta sin quejarse: nadie revisa el contenido hasta que llega a la báscula real, y ahí, en pleno proceso, todo se detiene porque nadie sabe qué hacer con "bastante". TypeScript es un revisor que lee el formulario antes de enviarlo y te dice, con el bolígrafo en la mano, "este campo debe ser un número" antes de que el paquete salga de la oficina.

JavaScript es un lenguaje de **tipado dinámico**: una variable puede guardar un texto en un momento y un número al siguiente, y el motor de JavaScript no se queja hasta que ejecuta la línea problemática, si es que llega a notarlo. Un ejemplo clásico:

```js
const price = "5";
const quantity = 3;

console.log(price + quantity); // "53", no 8
```

`price` es un texto, no un número. El operador `+` sobre un texto y un número no suma: concatena. El programa no falla, no lanza ningún error: simplemente produce un resultado incorrecto que puede pasar inadvertido hasta que alguien revisa un recibo y ve un total absurdo.

**TypeScript** es un superconjunto de JavaScript: todo programa JavaScript válido es también un programa TypeScript válido. Lo que agrega es una capa de anotaciones de tipo que un programa aparte, el **compilador de TypeScript** (`tsc`), revisa antes de ejecutar nada. Si anotas `price` como `number` y le asignas `"5"`, `tsc` se detiene y te lo dice:

```ts
const price: number = "5";
// Type '"5"' is not assignable to type 'number'.
```

Ese error nunca llega a ejecutarse. Aparece en el editor mientras escribes, o en la terminal cuando corres `tsc`, no en la consola del navegador. Esta es la diferencia central que vas a usar durante toda la etapa:

- Un **error en tiempo de ejecución** (como `"5" + 3` dando `"53"`) ocurre mientras el programa corre y a veces ni siquiera se nota.
- Un **error de tipos** ocurre antes: el compilador compara lo que anotaste con lo que realmente pasa y avisa sin correr una sola línea.

<Callout kind="warning">
  El `Playground` de esta plataforma ejecuta TypeScript quitando las anotaciones de tipo con una herramienta llamada Sucrase, para que el código corra al instante y sin conexión. Sucrase no revisa tipos: solo borra `: number`, `: string`, etc., y ejecuta el JavaScript que queda. Por eso, en esta etapa, un `Playground lang="ts"` con un error de tipos **va a ejecutarse igual** y mostrar el mismo resultado incorrecto que su versión en JavaScript. El error de tipos real solo aparece en tu editor o al correr `tsc`, que vas a ver simulado con el componente `Terminal`.
</Callout>

Instalar TypeScript y usar `tsc` es el tema de la lección 7. Por ahora, lo importante es entender el modelo mental: anotar tipos no cambia cómo corre el JavaScript resultante, cambia qué errores puedes detectar antes de correrlo. La documentación oficial lo resume así: [TypeScript for the New Programmer](https://www.typescriptlang.org/docs/handbook/typescript-in-5-minutes.html).

## Práctica

Ejecuta primero la versión en JavaScript y observa el resultado incorrecto. Después ejecuta la versión en TypeScript: el código es casi idéntico, con `price` anotado como `number`, pero el resultado es el mismo, porque el `Playground` no revisa tipos, solo los quita y ejecuta.

<Playground
  lang="js"
  code={`const price = "5";
const quantity = 3;

console.log(price + quantity);`}
  expected={`53`}
/>

<Playground
  lang="ts"
  code={`const price: number = "5";
const quantity: number = 3;

console.log(price + quantity);`}
  expected={`53`}
/>

Ahora mira lo que un compilador real reporta para ese mismo archivo. Este es el error que tu editor te mostraría de inmediato, y el que `tsc` imprime si lo corres desde la terminal:

## Errores comunes

**Pensar que `lang="ts"` en el Playground revisa tipos.** El Playground de esta plataforma solo quita las anotaciones con Sucrase y ejecuta el JavaScript resultante; no hay ningún paso de verificación. Cómo detectarlo: un `Playground lang="ts"` con un error de tipos evidente igual se ejecuta y produce salida, sin ningún aviso.

**Confundir un error de tipos con un error en tiempo de ejecución.** `"5" + 3` no es un error de tipos: es JavaScript válido que hace coerción de texto. TypeScript solo lo marca como error si anotaste `price` como `number` explícitamente. Cómo detectarlo: si el código corre y produce un resultado, aunque sea incorrecto, no fue un error de tipos; si el compilador se detiene antes de generar salida, sí lo fue.

**Esperar que TypeScript cambie el comportamiento en tiempo de ejecución.** Anotar tipos no agrega revisiones al JavaScript final: `tsc` borra las anotaciones al compilar, igual que Sucrase, solo que antes de borrarlas las compara con el código real. Cómo detectarlo: el JavaScript compilado de un archivo `.ts` no contiene ninguna anotación de tipo, ábrelo y compáralo.
