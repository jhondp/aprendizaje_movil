## Objetivo

Al terminar esta lección vas a poder anotar variables con `string`, `number`, `boolean`, arrays y tuplas, y explicar por qué `unknown` es la alternativa segura a `any`.

**Prerrequisitos:** `02-typescript/00-por-que-tipos`

## Concepto

Piensa en las etiquetas de los cajones de una cocina: uno dice "cubiertos", otro "servilletas", otro "especias". La etiqueta no cambia lo que hay adentro, pero avisa de inmediato si alguien intenta guardar una sartén en el cajón de las servilletas. Los tipos básicos de TypeScript son esas etiquetas para tus variables.

### Los tipos primitivos

```ts
const name: string = "Ana";
const age: number = 32;
const isActive: boolean = true;
```

`string`, `number` y `boolean` cubren texto, números (TypeScript no distingue enteros de decimales, todo es `number`) y verdadero/falso. En la mayoría de los casos no hace falta escribir la anotación: TypeScript la **infiere** a partir del valor inicial.

```ts
const name = "Ana"; // TypeScript infiere: string
```

La anotación explícita (`: string`) es útil cuando declaras una variable sin valor inicial, o cuando quieres dejar constancia del tipo esperado en una firma de función, tema de la próxima lección.

### Arrays

Un array de un tipo se escribe con corchetes después del tipo, o con la forma genérica `Array<T>` (equivalentes, la primera es más común):

```ts
const scores: number[] = [10, 8, 9];
const names: Array<string> = ["Ana", "Luis"];
```

Si intentas `scores.push("diez")`, el compilador rechaza el `"diez"` porque el array está anotado como `number[]`.

### Tuplas

Un array normal no limita cuántos elementos tiene ni en qué posición va cada tipo. Una **tupla** sí: es un array de longitud fija donde cada posición tiene su propio tipo.

```ts
const point: [number, number] = [3, 4];
const entry: [string, number] = ["temperatura", 21.5];
```

`point[0]` es siempre `number`, y `point` no puede tener un tercer elemento. Las tuplas son útiles para representar pares con significado fijo, como coordenadas o pares clave-valor, sin necesitar una interfaz completa (tema de la lección siguiente).

### `any`: la escotilla de escape que hay que evitar

`any` le dice a TypeScript "deja de revisar esta variable". Cualquier operación sobre un valor `any` se acepta sin comprobar nada:

```ts
let data: any = "hola";
data = 42; // sin error
data.toUpperCase(); // sin error, aunque data ahora es un número
```

La última línea es un error en tiempo de ejecución esperando a suceder: `42.toUpperCase()` no existe, pero TypeScript no lo advierte porque `any` desactivó toda revisión. Usar `any` es renunciar al motivo por el que elegiste TypeScript. Aparece casi siempre como una salida rápida bajo presión de tiempo, y conviene tratarlo como una deuda técnica marcada, nunca como una opción por defecto.

### `unknown`: la alternativa segura

`unknown` también acepta cualquier valor, pero no permite operar sobre él sin antes comprobar de qué tipo es realmente:

```ts
let data: unknown = "hola";
data = 42;
data.toString(); // error: Object is of type 'unknown'.

if (typeof data === "number") {
  data.toString(); // ahora sí: TypeScript sabe que aquí data es number
}
```

Esa comprobación (`typeof data === "number"`) se llama **narrowing** (acotar el tipo) y es el tema completo de la lección 5. Por ahora, la regla práctica es: cuando no sepas el tipo exacto de un valor de antemano (una respuesta de red, la entrada de un usuario), anota `unknown` en vez de `any`, y deja que el compilador te obligue a comprobar antes de usar. Documentación oficial: [Everyday Types](https://www.typescriptlang.org/docs/handbook/2/everyday-types.html).

## Errores comunes

**Usar `any` para "que compile rápido".** `any` desactiva toda revisión sobre esa variable, incluyendo errores reales como llamar a un método que no existe. Cómo detectarlo: revisa el código en busca de la palabra `any`; cada aparición es una zona donde TypeScript no te protege.

**Tratar `unknown` como si fuera `any`.** Asignar un valor a una variable `unknown` es libre, pero usarlo (llamar a un método, sumarlo) sin antes comprobar su tipo con `typeof` o similar produce un error de compilación. Cómo detectarlo: el compilador dice algo como "Object is of type 'unknown'" en la línea donde intentas operar sin comprobar antes.

**Confundir un array con una tupla.** `number[]` acepta cualquier cantidad de números; `[number, number]` exige exactamente dos. Si necesitas un par con significado fijo (como una coordenada) y usas `number[]`, pierdes la garantía de longitud. Cómo detectarlo: si accedes a `point[2]` y el tipo lo permite sin protestar, es un array, no una tupla.
