## Objetivo

Al terminar esta lección vas a poder declarar una unión de tipos, restringir un valor a un conjunto fijo de literales y modelar un estado con una unión discriminada.

**Prerrequisitos:** `02-typescript/02-interfaces-y-types`

## Concepto

Piensa en un semáforo. Solo puede estar en tres estados: rojo, amarillo o verde. No existe un cuarto estado ni un valor a mitad de camino: el semáforo es exactamente uno de esos tres. Una **unión** (`union`) en TypeScript describe justo eso: un valor que puede ser de uno de varios tipos posibles, nunca de otro.

### Unión de tipos

El operador `|` combina tipos:

```ts
function printId(id: string | number): void {
  console.log("ID:", id);
}

printId(42);
printId("abc-123");
```

`id` puede ser `string` o `number`, pero nada más: pasar un `boolean` es un error de compilación.

### Tipos literales

Un tipo literal restringe un valor a un texto o número exacto, no a todo el conjunto de `string` o `number`:

```ts
let direction: "left" | "right";

direction = "left";  // válido
direction = "up";    // error: Type '"up"' is not assignable to type '"left" | "right"'.
```

`"left" | "right"` es una unión de dos tipos literales: el valor solo puede ser uno de esos dos textos exactos. Esto reemplaza al patrón, común en JavaScript, de comentar "acá solo va 'left' o 'right'" con un comentario que nadie garantiza que se respete: TypeScript lo hace cumplir.

### El semáforo, modelado

```ts
type Status = "todo" | "done";

let taskStatus: Status = "todo";
taskStatus = "done";     // válido
taskStatus = "pending";  // error: no es uno de los literales permitidos
```

`Status` documenta, en el propio tipo, cuáles son los únicos valores posibles. Cualquiera que lea la firma de una función que recibe `Status` sabe exactamente qué esperar, sin necesitar un comentario aparte.

### Unión discriminada

Cuando cada posible "forma" de un valor necesita datos distintos, una unión de literales sueltos no alcanza. Ahí entra la **unión discriminada**: varias interfaces que comparten un campo común (el discriminante) con un valor literal distinto en cada una.

```ts
interface Loading {
  kind: "loading";
}

interface Success {
  kind: "success";
  data: string;
}

interface Failure {
  kind: "failure";
  error: string;
}

type FetchState = Loading | Success | Failure;

function describe(state: FetchState): string {
  if (state.kind === "success") {
    return "Datos: " + state.data;
  }
  if (state.kind === "failure") {
    return "Error: " + state.error;
  }
  return "Cargando...";
}
```

El campo `kind` es el discriminante: su valor literal (`"loading"`, `"success"`, `"failure"`) le dice a TypeScript cuál de las tres formas tiene el objeto en cada rama del `if`. Dentro de `if (state.kind === "success")`, TypeScript ya sabe que `state` tiene la propiedad `data`, y te avisaría si intentas acceder a `state.error` en esa misma rama. Este mecanismo de "reducir" una unión a una forma concreta según una comprobación se llama **narrowing** y es el tema completo de la lección 5. Documentación oficial: [Narrowing — Discriminated unions](https://www.typescriptlang.org/docs/handbook/2/narrowing.html#discriminated-unions).

## Errores comunes

**Asignar un valor fuera de la unión literal.** `let direction: "left" | "right"; direction = "up";` falla en compilación porque `"up"` no es uno de los literales permitidos. Cómo detectarlo: el mensaje de error lista exactamente los literales válidos entre comillas.

**Acceder a una propiedad de una rama distinta antes de comprobar el discriminante.** Dentro de una función que recibe `FetchState`, escribir `state.data` sin antes comprobar `state.kind === "success"` falla porque `Loading` y `Failure` no tienen `data`. Cómo detectarlo: el compilador dice algo como "Property 'data' does not exist on type 'Loading | Failure'".

**Olvidar un caso al ramificar sobre una unión.** Si `FetchState` tuviera un cuarto estado y la función solo comprueba dos de los cuatro, ese cuarto caso cae en un `else` genérico sin que nadie lo note. Cómo detectarlo: la lección 5 muestra cómo un `switch` exhaustivo hace que el compilador marque un error si falta cubrir un caso.
