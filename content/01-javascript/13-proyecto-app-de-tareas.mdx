## Objetivo

Al terminar esta lección habrás construido, en un solo archivo `todo.js`, una app de tareas en consola que agrega, completa, lista y filtra tareas, combinando todo lo aprendido en esta etapa.

**Prerrequisitos:** `01-javascript/12-async-await-y-fetch`

## Concepto

En [el proyecto de la etapa anterior](/etapa/00-aprender-a-programar/07-proyecto-tu-primer-repo) creaste tu primer repositorio con un README que explicaba un programa simple. Esta vez el repositorio va a contener código real: un programa que guarda datos, los transforma y responde a distintas operaciones, todo con las herramientas de esta etapa.

### Qué vas a construir

Una app de tareas en consola, en un único archivo `todo.js`, que se ejecuta con `node todo.js`. El estado de la app es un array de objetos con esta forma:

```js
{ id: 1, title: "Buy milk", done: false }
```

La app expone cuatro operaciones, como funciones:

- `addTask(title)`: crea una tarea nueva con un `id` único y `done: false`, la agrega al array, y la devuelve.
- `completeTask(id)`: busca la tarea con ese `id` y marca `done` en `true`.
- `listTasks()`: devuelve todas las tareas.
- `pendingTasks()`: devuelve solo las tareas con `done: false`, usando `filter`.

### Por qué un closure y no variables sueltas

Si `tasks` y el contador de ids fueran variables sueltas en el archivo, cualquier parte del código podría modificarlas directamente, sin pasar por `addTask` o `completeTask`, y sería fácil olvidar incrementar el contador o dejar el array en un estado inconsistente. La solución de esta lección es la misma idea que viste en scope y closures: una función `createTaskStore` que declara `tasks` y `nextId` como variables privadas, y devuelve un objeto con las únicas funciones autorizadas para tocarlas.

```js
function createTaskStore() {
  let tasks = [];
  let nextId = 1;

  function addTask(title) {
    const task = { id: nextId, title, done: false };
    tasks.push(task);
    nextId += 1;
    return task;
  }

  function completeTask(id) {
    const task = tasks.find((t) => t.id === id);
    if (!task) {
      throw new Error(`Task ${id} not found`);
    }
    task.done = true;
    return task;
  }

  function listTasks() {
    return tasks;
  }

  function pendingTasks() {
    return tasks.filter((t) => !t.done);
  }

  return { addTask, completeTask, listTasks, pendingTasks };
}
```

`tasks` y `nextId` no aparecen en el objeto que `createTaskStore` devuelve: son privados, igual que la variable `count` del closure contador. La única forma de leerlos o modificarlos es a través de `addTask`, `completeTask`, `listTasks` y `pendingTasks`.

### Qué significa terminado

El proyecto está terminado cuando, ejecutando `node todo.js`, la consola muestra: la lista completa de tareas después de agregar al menos tres, el resultado de completar una de ellas, y la lista de tareas pendientes filtrada correctamente. El `Challenge` de esta lección agrega una quinta operación, `removeTask`, para seguir practicando.

## Errores comunes

**Reutilizar el mismo id al agregar varias tareas.** Si `nextId` no se incrementa después de crear una tarea, dos tareas terminan con el mismo `id`, y `completeTask` o `removeTask` afectan a la primera que `find` o `filter` encuentren, no necesariamente a la esperada. Se detecta comparando los `id` de `listTasks()`: si hay dos iguales, falta el `nextId += 1`.

**Exponer `tasks` directamente en el objeto devuelto.** Si `createTaskStore` devuelve `{ tasks, addTask, ... }`, cualquier código externo puede hacer `store.tasks.push(...)` sin pasar por `addTask`, saltándose la asignación del `id`. Se detecta revisando qué propiedades tiene el objeto devuelto: solo deberían estar las funciones, nunca el array `tasks` en sí.

**Llamar a completeTask con un id de tipo distinto al guardado.** Si las tareas se crean con `id` numérico pero `completeTask("2")` se llama con un string, `t.id === id` es `false` para todas las tareas porque `===` no convierte tipos, y la función lanza `Task 2 not found` aunque la tarea exista. Se detecta comparando el tipo del argumento contra el tipo real de `id` en los objetos de `tasks`.
