## Objetivo

Al terminar esta lección podrás usar `setTimeout` con un callback, crear una `Promise`, y manejar su resultado con `.then` y `.catch`.

**Prerrequisitos:** `01-javascript/10-modulos`

## Concepto

Todo el código que escribiste hasta ahora es síncrono: cada línea espera a que termine la anterior antes de ejecutarse. Pero algunas operaciones tardan un tiempo real en completarse, como pedir datos a un servidor o esperar a que el usuario responda. JavaScript no se queda "congelado" esperando: sigue con el resto del programa y avisa cuando la operación termina. Es como pedir comida a domicilio: no te quedas parado en la puerta sin hacer nada hasta que llega, sigues con tus tareas y el timbre te avisa cuando el pedido está listo.

### Código asíncrono con callbacks

Un callback es una función que se pasa como argumento para que se ejecute más adelante, cuando la operación asíncrona termina. `setTimeout` es el ejemplo más simple: ejecuta una función después de esperar una cantidad de milisegundos.

```js
console.log("1: empieza el programa");

setTimeout(() => {
  console.log("3: pasaron 1000 ms");
}, 1000);

console.log("2: esto se imprime antes, sin esperar");
```

El orden de impresión es `1`, `2`, `3`: aunque `setTimeout` aparece antes que la última línea en el código, JavaScript no espera esos 1000 ms ahí mismo. Sigue ejecutando el resto del programa y solo llama al callback cuando el tiempo pasó.

### El problema de encadenar callbacks

Cuando una operación asíncrona depende del resultado de otra, encadenar callbacks uno dentro de otro se vuelve difícil de leer.

```js
setTimeout(() => {
  console.log("paso 1");
  setTimeout(() => {
    console.log("paso 2");
    setTimeout(() => {
      console.log("paso 3");
    }, 500);
  }, 500);
}, 500);
```

Cada paso depende de anidar una función más dentro de la anterior. Esto se conoce como "callback hell" y es una de las razones por las que JavaScript incorporó las promesas.

### Promise: representar un resultado futuro

Una `Promise` es un objeto que representa un valor que todavía no existe, pero que existirá (o fallará) en algún momento. Se crea con `new Promise`, que recibe una función con dos parámetros: `resolve` (para avisar éxito) y `reject` (para avisar fallo).

```js
const fetchUser = new Promise((resolve, reject) => {
  setTimeout(() => {
    const success = true;
    if (success) {
      resolve({ id: 1, name: "Ana" });
    } else {
      reject(new Error("No se pudo obtener el usuario"));
    }
  }, 500);
});
```

Nada dentro de la función se ejecuta al crear la `Promise`: la operación asíncrona (aquí, el `setTimeout`) empieza en cuanto se llama a `new Promise(...)`, pero el resultado llega después.

### then y catch

`.then` recibe una función que se ejecuta cuando la promesa se resuelve con éxito, con el valor pasado a `resolve` como argumento. `.catch` recibe una función que se ejecuta cuando la promesa falla, con el error pasado a `reject`.

```js
fetchUser
  .then((user) => {
    console.log("Usuario recibido:", user.name);
  })
  .catch((error) => {
    console.log("Falló:", error.message);
  });
```

`.then` y `.catch` se pueden encadenar: cada `.then` puede devolver un valor o una nueva promesa, y el siguiente `.then` de la cadena recibe ese resultado, en lugar de anidar callbacks dentro de callbacks.

Puedes revisar la referencia completa de `Promise` en MDN: https://developer.mozilla.org/es/docs/Web/JavaScript/Reference/Global_Objects/Promise.

## Errores comunes

**Esperar que el código después de setTimeout se ejecute después del callback.** `setTimeout` no pausa el programa: la línea siguiente al `setTimeout` se ejecuta de inmediato, antes de que pase el tiempo indicado. Se detecta comparando el orden real de los mensajes impresos contra el orden en que las líneas aparecen escritas en el código.

**Olvidar llamar a resolve o reject dentro de la Promise.** Si la función que recibe `new Promise` nunca llama a `resolve` ni a `reject`, ni `.then` ni `.catch` se ejecutan jamás: la promesa queda "pendiente" para siempre. Se detecta porque el programa no imprime nada relacionado con esa promesa, sin ningún error visible.

**Olvidar el .catch y dejar un error sin manejar.** Si una promesa se rechaza y no hay ningún `.catch` en la cadena, el error no se maneja y puede aparecer como "Unhandled promise rejection" en la consola. Se detecta por ese mensaje; la solución es agregar siempre un `.catch` a cada cadena de promesas que pueda fallar.
