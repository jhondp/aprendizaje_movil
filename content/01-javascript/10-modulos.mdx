## Objetivo

Al terminar esta lección podrás dividir código en varios archivos usando `export` e `import`, y ejecutar esos archivos con Node.js.

**Prerrequisitos:** `01-javascript/09-errores-y-debugging`

## Concepto

Hasta ahora todo tu código vivió en un solo archivo. A medida que un programa crece, un solo archivo se vuelve difícil de leer: es como guardar toda la ropa de la casa en una sola caja, sin separar por habitación. Un módulo es un archivo que expone solo una parte de su contenido a los demás archivos, con `export`, y que puede tomar lo que otros archivos exponen, con `import`. El resto de su contenido queda privado, visible solo dentro de ese archivo.

### export: exponer una función

`export` delante de una declaración la hace disponible para otros archivos.

```js
// math.js
export function add(a, b) {
  return a + b;
}

export function multiply(a, b) {
  return a * b;
}
```

Cualquier función, constante o variable sin `export` delante permanece privada de ese archivo: ningún otro archivo puede acceder a ella directamente.

### import: usar lo que otro archivo exportó

`import` trae al archivo actual las funciones o valores que otro archivo exportó, usando llaves con los nombres exactos y una ruta relativa al archivo de origen.

```js
// main.js
import { add, multiply } from "./math.js";

console.log(add(2, 3)); // 5
console.log(multiply(2, 3)); // 6
```

La ruta `"./math.js"` es relativa al archivo `main.js`: `./` significa "en esta misma carpeta". En Node.js, a diferencia de otras herramientas, la extensión `.js` en la ruta es obligatoria.

### Habilitar módulos ES en Node.js

Node.js necesita saber que un proyecto usa módulos ES (la sintaxis `export`/`import` de este curso), en lugar del sistema más antiguo `require`. La forma más común es agregar `"type": "module"` al `package.json` del proyecto.

```json
{
  "name": "todo-app",
  "type": "module"
}
```

Con esa línea, cualquier archivo `.js` del proyecto puede usar `export` e `import`. Sin ella, Node.js interpreta `import` como un error de sintaxis.

Puedes revisar la referencia completa de módulos ES en Node.js: https://nodejs.org/api/esm.html, y la guía de módulos de JavaScript en MDN: https://developer.mozilla.org/es/docs/Web/JavaScript/Guide/Modules.

  El proyecto de cierre de esta etapa, la app de tareas, puede vivir en un solo archivo por simplicidad. Vas a dividir código en varios archivos con export/import en proyectos más grandes, a partir de la etapa 3.
</Callout>

## Errores comunes

**Olvidar `"type": "module"` en `package.json`.** Sin esa línea, Node.js lanza `SyntaxError: Cannot use import statement outside a module` al encontrar la primera línea `import`. Se detecta por ese mensaje exacto; la solución es agregar `"type": "module"` al `package.json`, o usar la extensión `.mjs` en los archivos.

**Omitir la extensión del archivo en la ruta de import.** `import { add } from "./math"` (sin `.js`) falla en Node.js con un error de tipo "Cannot find module", porque Node.js, a diferencia de otras herramientas, no adivina la extensión. Se detecta por ese mensaje; la solución es escribir la ruta completa, `"./math.js"`.

**Importar sin llaves algo que se exportó con nombre.** `import add from "./math.js"` (sin llaves) busca una exportación por defecto que no existe en `math.js`, así que `add` termina siendo `undefined`. Se detecta porque la función "existe" pero llamarla lanza `TypeError: add is not a function`. Solución: usar llaves con el nombre exacto exportado, `import { add } from "./math.js"`.
