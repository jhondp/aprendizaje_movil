## Objetivo

Al terminar esta lección podrás declarar una función `async`, usar `await` para esperar el resultado de una promesa, manejar errores con `try`/`catch`, y describir cómo `fetch` pide datos a una API.

**Prerrequisitos:** `01-javascript/11-callbacks-y-promesas`

## Concepto

`.then` y `.catch` funcionan bien, pero encadenar varios se puede volver difícil de seguir, igual que pasaba con los callbacks anidados. `async`/`await` es una forma de escribir código basado en promesas que se lee de arriba hacia abajo, como una receta de cocina normal: "espera a que el agua hierva, después agrega la pasta", en lugar de "cuando el agua hierva, llama a esta función para agregar la pasta".

### Declarar una función async

La palabra clave `async` delante de una función indica que esa función siempre devuelve una promesa, incluso si dentro solo hay un `return` con un valor simple.

```js
async function greet() {
  return "hello";
}

greet().then((message) => console.log(message)); // hello
```

### await: esperar una promesa sin bloquear el resto del programa

Dentro de una función `async`, `await` pausa la ejecución de esa función hasta que la promesa a su derecha se resuelve, y devuelve el valor resuelto directamente, sin necesidad de `.then`. El resto del programa, fuera de esa función, sigue ejecutándose mientras tanto.

```js
function wait(ms, value) {
  return new Promise((resolve) => {
    setTimeout(() => resolve(value), ms);
  });
}

async function run() {
  console.log("start");
  const result = await wait(300, "done waiting");
  console.log(result);
  console.log("end");
}

run();
console.log("this line runs before run() finishes");
```

`await` solo puede usarse dentro de una función marcada como `async`; escribirlo en una función normal es un error de sintaxis.

### try/catch con await

Cuando una promesa esperada con `await` se rechaza, `await` lanza ese error, así que puedes atraparlo con el `try`/`catch` de la lección anterior.

```js
async function verify(age) {
  try {
    const message = await checkAge(age); // checkAge devuelve una Promise, como en la lección anterior
    console.log(message);
  } catch (error) {
    console.log("error:", error.message);
  }
}
```

### fetch: pedir datos a una API real

`fetch(url)` pide datos a una dirección web y devuelve una `Promise` que se resuelve con un objeto `Response`. Ese objeto todavía no tiene los datos listos para usar: hay que llamar a `response.json()`, que también devuelve una promesa, para obtener el cuerpo de la respuesta ya convertido de JSON a un valor de JavaScript.

```js
async function getTodo() {
  try {
    const response = await fetch("https://jsonplaceholder.typicode.com/todos/1");
    const data = await response.json();
    console.log(data);
  } catch (error) {
    console.log("Request failed:", error.message);
  }
}

getTodo();
// { userId: 1, id: 1, title: "delectus aut autem", completed: false }
```

Este ejemplo depende de un servidor externo y de tu conexión, así que se deja aquí como código de referencia: la práctica de abajo simula la respuesta para que el ejercicio funcione igual sin conexión. Puedes revisar la referencia completa de `fetch` en MDN: https://developer.mozilla.org/es/docs/Web/API/Fetch_API/Using_Fetch.

<Callout kind="warning">

</Callout>

## Errores comunes

**Usar await fuera de una función async.** Escribir `await` en una función normal (sin `async` delante) es un error de sintaxis: `SyntaxError: await is only valid in async functions`. Se detecta por ese mensaje; la solución es agregar `async` a la declaración de la función.

**Olvidar el await y trabajar con la promesa en vez de su valor.** `const result = wait(300, "done"); console.log(result);` imprime un objeto `Promise` pendiente, no `"done"`, porque falta el `await` que espera la resolución. Se detecta porque el valor impreso es `Promise { <pending> }` en lugar del dato esperado.

**Olvidar que una función async siempre devuelve una promesa.** `const value = getUserName(1); console.log(value);` imprime una `Promise`, no el nombre, aunque `getUserName` termine con un `return` directo. Se detecta de la misma forma que el error anterior: hay que usar `await` (dentro de otra función `async`) o `.then` para obtener el valor real.
