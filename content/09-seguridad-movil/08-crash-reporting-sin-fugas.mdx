## Objetivo

Al terminar esta lección podrás configurar `@sentry/react-native` en una app Expo con `beforeSend` y `beforeBreadcrumb` que eliminen datos personales y secretos antes de que salgan del dispositivo, y comprobar con un evento de prueba que la limpieza funciona.

**Prerrequisitos:** `09-seguridad-movil/07-privacidad-y-permisos-minimos`

## Concepto

Esta lección cubre **MASVS-STORAGE-2** (evitar la fuga de datos sensibles, aquí hacia un servicio externo) y **MASVS-PRIVACY-1** (minimizar los datos que se comparten con terceros).

### El informe del taller

Cuando llevas el coche al taller, el mecánico necesita saber qué ruido hacía, cuándo y a qué velocidad. No necesita el contenido de tu guantera. Un reporte de fallo es lo mismo: pila de llamadas, versión de la app, modelo de dispositivo y los pasos previos. No necesita el correo del usuario, su token de sesión ni el texto de la nota que estaba escribiendo. El problema es que las herramientas de crash reporting, por defecto, recogen mucho contexto porque no saben qué parte es sensible. Decidirlo es tu trabajo.

### Qué envía un reporte

Un evento típico de Sentry incluye: el error y su pila, tags (versión, plataforma, entorno), `user` (lo que tú establezcas), `extra` (lo que tú adjuntes), `breadcrumbs` (una traza de lo que pasó antes: navegación, peticiones HTTP, mensajes de `console.log`) y, opcionalmente, información del dispositivo. Tres de esas partes son las que filtran datos con más frecuencia:

- **`user`**: si llamas a `Sentry.setUser({ email })`, el correo viaja con cada evento.
- **`breadcrumbs`**: cada `console.log` de tu app se convierte en una miga. Si en algún lugar registras el cuerpo de una petición o una nota, viaja.
- **`extra` y mensajes de error**: `throw new Error("Failed to save note: " + note.body)` envía el contenido de la nota como parte del mensaje.

### Instalar en Expo

Expo recomienda `@sentry/react-native` con su config plugin; el antiguo paquete `sentry-expo` está descontinuado. La guía oficial usa el asistente: `npx @sentry/wizard@latest -i reactNative`, que instala el paquete, configura Metro y añade `@sentry/react-native/expo` a los plugins de `app.json` ([https://docs.expo.dev/guides/using-sentry/](https://docs.expo.dev/guides/using-sentry/)). La configuración del SDK va en el layout raíz de Expo Router, y ahí es donde aplicas la política de privacidad del reporte.

### La configuración que no filtra

```ts
// src/app/_layout.tsx
import * as Sentry from "@sentry/react-native";
import { scrubEvent, dropSensitiveBreadcrumb } from "@/infrastructure/monitoring/scrub";

Sentry.init({
  dsn: process.env.EXPO_PUBLIC_SENTRY_DSN,
  environment: process.env.EXPO_PUBLIC_ENVIRONMENT ?? "production",
  enabled: !__DEV__,
  sendDefaultPii: false,
  beforeSend: scrubEvent,
  beforeBreadcrumb: dropSensitiveBreadcrumb,
});
```

`sendDefaultPii: false` evita que el SDK adjunte por su cuenta datos identificativos como la dirección IP. El DSN es configuración pública (solo permite enviar eventos a tu proyecto, no leerlos), así que puede ir en `EXPO_PUBLIC_`. `enabled: !__DEV__` evita ruido y fugas durante el desarrollo.

`beforeSend` recibe cada evento justo antes de enviarlo: puedes modificarlo o devolver `null` para descartarlo. Es la última línea de defensa y debe cubrir tres cosas: eliminar el correo del usuario, enmascarar cualquier cadena que parezca token o correo, y vaciar los campos que tu app usa para contenido. Ojo con dónde viaja cada dato: el texto de un `Error` lanzado no va en `event.message` sino en `event.exception.values[].value`, y también pueden llevar datos personales los `tags`, los `contexts`, la `request` (URL, query string, cabeceras), las variables de los frames de la pila y las migas ya adjuntas. La limpieza recorre todos esos lugares:

```ts
// src/infrastructure/monitoring/scrub.ts
import type { Breadcrumb, ErrorEvent } from "@sentry/react-native";

const EMAIL = /[\w.+-]+@[\w-]+\.[\w.-]+/g;
const BEARER = /Bearer\s+[A-Za-z0-9._-]+/g;
const SENSITIVE_KEYS = new Set(["password", "token", "authorization", "cookie", "body", "notebody", "email"]);

export function scrubText(text: string): string {
  return text.replace(EMAIL, "[email]").replace(BEARER, "Bearer [token]");
}

export function scrubValue(value: unknown): unknown {
  if (typeof value === "string") return scrubText(value);
  if (Array.isArray(value)) return value.map(scrubValue);
  if (value && typeof value === "object") {
    const out: Record<string, unknown> = {};
    for (const [key, inner] of Object.entries(value)) {
      out[key] = SENSITIVE_KEYS.has(key.toLowerCase()) ? "[redacted]" : scrubValue(inner);
    }
    return out;
  }
  return value;
}

export function scrubEvent(event: ErrorEvent): ErrorEvent {
  if (event.user) event.user = { id: event.user.id };
  if (event.message) event.message = scrubText(event.message);
  for (const exception of event.exception?.values ?? []) {
    if (exception.value) exception.value = scrubText(exception.value);
    for (const frame of exception.stacktrace?.frames ?? []) {
      if (frame.vars) frame.vars = scrubValue(frame.vars) as Record<string, unknown>;
    }
  }
  if (event.extra) event.extra = scrubValue(event.extra) as ErrorEvent["extra"];
  if (event.tags) event.tags = scrubValue(event.tags) as ErrorEvent["tags"];
  if (event.contexts) event.contexts = scrubValue(event.contexts) as ErrorEvent["contexts"];
  if (event.request) {
    delete event.request.cookies;
    event.request = scrubValue(event.request) as ErrorEvent["request"];
  }
  if (event.breadcrumbs) {
    event.breadcrumbs = event.breadcrumbs.map((crumb) => scrubValue(crumb) as Breadcrumb);
  }
  return event;
}

export function dropSensitiveBreadcrumb(crumb: Breadcrumb): Breadcrumb | null {
  if (crumb.category === "console") return null;
  if (crumb.message) crumb.message = scrubText(crumb.message);
  if (crumb.data) crumb.data = scrubValue(crumb.data) as Record<string, unknown>;
  return crumb;
}
```

Descartar las migas de categoría `console` es una decisión deliberada: los `console.log` de desarrollo son la vía más frecuente de fuga y, en producción, no deberían existir. Si necesitas trazas, usa `Sentry.addBreadcrumb` con datos que tú controlas.

### Identificar sin exponer

Para agrupar errores por usuario basta con el identificador de cuenta: `Sentry.setUser({ id: account.id })`. Nunca el correo ni el nombre. Y cuando el usuario cierra sesión, `Sentry.setUser(null)`.

### Lo que no debe entrar en un mensaje de error

La regla más barata de todas: los mensajes de error describen **qué** falló, no **con qué datos**. `new Error("Failed to save note")` más un tag `noteId` es suficiente para depurar. El contenido de la nota nunca aporta nada al diagnóstico y siempre es una fuga.

<Callout kind="warning">
  Prueba la limpieza antes del release: lanza un error de prueba con un correo y un token falsos en el mensaje y en `extra`, y revisa el evento recibido en el panel del proveedor. Si aparece algo que no debería, `beforeSend` tiene un hueco.
</Callout>

## Errores comunes

**Establecer el usuario con su correo.** `Sentry.setUser({ email })` parece inofensivo y convierte cada evento en un dato personal exportado a un tercero. Ocurre porque el panel muestra el correo y resulta cómodo. Se detecta abriendo cualquier evento en el panel: si ves un correo, hay fuga.

**Dejar las migas de consola activas.** Los `console.log` de depuración, incluidos los que imprimen respuestas de la API, viajan con cada evento. Ocurre porque la integración de consola está activa por defecto. Se detecta revisando las breadcrumbs de un evento: cualquier miga con categoría `console` y datos de la app es un hallazgo.

**Poner datos en el mensaje del error.** `new Error("Cannot sync: " + JSON.stringify(note))` describe el fallo con el contenido completo. Ocurre por comodidad al depurar. Se detecta buscando concatenaciones dentro de `new Error(` en el proyecto.

**Confiar solo en el enmascarado del servidor.** El proveedor ofrece reglas de limpieza en su lado, y se asume que basta. Ocurre porque es más fácil de configurar. Pero el dato ya salió del dispositivo y cruzó la red; la limpieza del servidor es complemento, no sustituto de `beforeSend`.
