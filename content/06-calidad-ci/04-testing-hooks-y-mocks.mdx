## Objetivo

Al terminar esta lección podrás probar un hook personalizado con `renderHook` y reemplazar un repositorio real por uno falso, ya sea inyectándolo o con `jest.mock`.

**Prerrequisitos:** `06-calidad-ci/03-jest-y-rntl`

## Concepto

Un piloto no aprende a aterrizar con tormenta en un avión real con pasajeros: usa un simulador. El simulador responde a los mandos igual que el avión, pero el clima, la pista y las fallas los controla el instructor. En las pruebas pasa lo mismo: no quieres que una prueba de pantalla dependa de SQLite, de la red o del reloj. Reemplazas esas piezas por **dobles de prueba** que se comportan como tú decides.

### Por qué la arquitectura ayuda

En la etapa anterior separaste la app de notas en capas y definiste un puerto `NotesRepository`. Esa decisión rinde frutos ahora: si la interfaz de usuario solo conoce el puerto, en las pruebas puedes darle cualquier implementación.

```ts
// src/features/notes/domain/Note.ts
export type Note = { id: string; title: string };

// src/features/notes/application/NotesRepository.ts (the port lives in application, as in stage 5)
import type { Note } from "../domain/Note";

export interface NotesRepository {
  list(): Promise<Note[]>;
  add(title: string): Promise<Note>;
}
```

```ts
// src/features/notes/ui/useNotes.ts
import { useEffect, useState } from "react";
import type { Note } from "../domain/Note";
import type { NotesRepository } from "../application/NotesRepository";

export function useNotes(repository: NotesRepository) {
  const [notes, setNotes] = useState<Note[]>([]);
  const [isLoading, setIsLoading] = useState(true);

  useEffect(() => {
    let active = true;
    repository.list().then((loaded) => {
      if (active) {
        setNotes(loaded);
        setIsLoading(false);
      }
    });
    return () => {
      active = false;
    };
  }, [repository]);

  const addNote = async (title: string) => {
    const note = await repository.add(title);
    setNotes((current) => [...current, note]);
  };

  return { notes, isLoading, addNote };
}
```

### Funciones simuladas con jest.fn

`jest.fn()` crea una función que registra cada llamada y devuelve lo que le indiques. Sirve para dos cosas: controlar respuestas (`mockResolvedValue` para promesas) y verificar interacciones (`toHaveBeenCalledWith`).

```ts
const list = jest.fn().mockResolvedValue([{ id: "1", title: "Comprar pan" }]);
await list();
expect(list).toHaveBeenCalledTimes(1);
```

### Probar un hook con renderHook

Un hook solo puede ejecutarse dentro de un componente. `renderHook` crea ese componente por ti y expone el valor devuelto en `result.current`. Como el hook carga datos de forma asíncrona, usas `waitFor` para esperar a que termine la carga, y `act` para envolver una acción que actualiza estado. En React Native Testing Library 14, `renderHook` y `act` también se usan con `await`.

```ts
// src/features/notes/ui/useNotes.test.ts
import { act, renderHook, waitFor } from "@testing-library/react-native";
import type { NotesRepository } from "../application/NotesRepository";
import { useNotes } from "./useNotes";

function createFakeRepository(): NotesRepository {
  return {
    list: jest.fn().mockResolvedValue([{ id: "1", title: "Comprar pan" }]),
    add: jest.fn(async (title: string) => ({ id: "2", title })),
  };
}

describe("useNotes", () => {
  test("loads notes from the repository", async () => {
    const repository = createFakeRepository();
    const { result } = await renderHook(() => useNotes(repository));

    await waitFor(() => expect(result.current.isLoading).toBe(false));
    expect(result.current.notes).toEqual([{ id: "1", title: "Comprar pan" }]);
  });

  test("adds a note through the repository", async () => {
    const repository = createFakeRepository();
    const { result } = await renderHook(() => useNotes(repository));
    await waitFor(() => expect(result.current.isLoading).toBe(false));

    await act(() => result.current.addNote("Llamar a Luis"));

    expect(repository.add).toHaveBeenCalledWith("Llamar a Luis");
    expect(result.current.notes).toHaveLength(2);
  });
});
```

Esta prueba no toca SQLite. El repositorio falso se **inyecta** como argumento: es la forma más simple de aislar código y no necesita ninguna magia de Jest.

### Reemplazar un módulo con jest.mock

A veces el componente importa directamente el adaptador real y no puedes pasarle otro. Por ejemplo, la pantalla principal:

```tsx
// src/features/notes/ui/NotesScreen.tsx
import { FlatList, Text } from "react-native";
import { sqliteNotesRepository } from "../infrastructure/sqliteNotesRepository";
import { useNotes } from "./useNotes";

export function NotesScreen() {
  const { notes, isLoading } = useNotes(sqliteNotesRepository);
  if (isLoading) return <Text>Cargando...</Text>;
  return (
    <FlatList
      data={notes}
      keyExtractor={(note) => note.id}
      renderItem={({ item }) => <Text>{item.title}</Text>}
    />
  );
}
```

`jest.mock(ruta, fábrica)` reemplaza el módulo completo en esa suite de pruebas. Jest eleva la llamada al inicio del archivo, antes de los `import`, así que la pantalla recibe la versión falsa:

```tsx
// src/features/notes/ui/NotesScreen.test.tsx
import { render, screen } from "@testing-library/react-native";
import { NotesScreen } from "./NotesScreen";

jest.mock("../infrastructure/sqliteNotesRepository", () => ({
  sqliteNotesRepository: {
    list: jest.fn().mockResolvedValue([{ id: "1", title: "Comprar pan" }]),
    add: jest.fn(),
  },
}));

test("shows the notes stored in the repository", async () => {
  await render(<NotesScreen />);

  expect(await screen.findByText("Comprar pan")).toBeOnTheScreen();
});
```

`findByText` espera a que la promesa del repositorio se resuelva y el texto aparezca. Para que los contadores de llamadas no pasen de una prueba a otra, agrega `"clearMocks": true` a la sección `jest` de `package.json`.

### Módulos nativos

`jest-expo` ya simula los módulos nativos del SDK de Expo, pero muchas bibliotecas de terceros publican su propio mock. AsyncStorage, por ejemplo, documenta este:

```ts
jest.mock("@react-native-async-storage/async-storage", () =>
  require("@react-native-async-storage/async-storage/jest/async-storage-mock"),
);
```

Regla práctica: inyecta dependencias cuando puedas y usa `jest.mock` para lo que no controlas. Cuantos más `jest.mock` necesita una prueba, más acoplado está el código que prueba. Referencias: https://jestjs.io/docs/mock-functions y https://oss.callstack.com/react-native-testing-library/docs/api/misc/render-hook

## Errores comunes

**Crear el doble dentro del callback de `renderHook`.** Escribes `renderHook(() => useNotes(createFakeRepository()))` y la prueba entra en un bucle o nunca termina de cargar. Ocurre porque cada render crea un repositorio nuevo, cambia la dependencia del efecto y el efecto vuelve a ejecutarse. Se detecta porque `list` aparece llamada muchas veces; la solución es crear el repositorio una vez, fuera del callback.

**Mockear lo que estás probando.** Una prueba de `useNotes` que hace `jest.mock("./useNotes")` siempre pasa, porque verifica el mock y no el código. Pasa al copiar mocks entre archivos sin pensar. Se detecta rompiendo a propósito el código real: si la prueba no falla, no lo está ejecutando.

**Estado de mocks que se filtra entre pruebas.** Una prueba pasa sola pero falla cuando se ejecuta con las demás, porque `toHaveBeenCalledTimes(1)` cuenta llamadas de la prueba anterior. Ocurre sin `clearMocks`. Se detecta ejecutando la prueba aislada con `npx jest -t "nombre de la prueba"` y comparando.
