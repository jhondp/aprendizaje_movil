## Objetivo

Al terminar esta lección podrás crear pantallas con Expo Router a partir de archivos, navegar entre ellas con `Link` y `router`, y leer el parámetro de una ruta dinámica con `useLocalSearchParams`.

**Prerrequisitos:** `04-react-native-expo/08-imagenes-fuentes-iconos`

## Concepto

Hasta ahora cada ejemplo fue una sola pantalla. Una app real tiene muchas: una lista, un detalle, un formulario, ajustes. Pasar de una a otra se llama **navegación**, y en móvil funciona distinto que en la web: cada pantalla nueva se apila encima de la anterior, con una animación, y el gesto o botón de volver la retira.

**Expo Router** es el sistema de navegación de Expo. Su idea central es que **cada archivo dentro de `src/app/` es una pantalla** y su ruta en el disco es su dirección. Es el mismo enfoque que usan frameworks web como Next.js.

Documentación oficial: https://docs.expo.dev/router/introduction/ y https://docs.expo.dev/router/basics/core-concepts/

### Una analogía: una pila de cartas

Imagina que lees cartas sobre una mesa. Tienes una carta abierta (la lista de notas). Cuando abres un sobre nuevo, pones esa carta encima de la anterior: solo ves la de arriba, pero la de abajo sigue ahí, tal como la dejaste. Cuando terminas, retiras la de arriba y vuelves a ver la anterior. Esa pila de cartas es un **stack** de navegación: `push` pone una pantalla encima y `back` la retira.

### Las rutas son archivos

Con la plantilla actual de Expo, las pantallas viven en `src/app/`. En proyectos creados con SDK anteriores al 55 la carpeta es `app/` en la raíz; las reglas son idénticas. Este curso usa `src/app/` en todas las etapas porque es lo que genera `create-expo-app@latest` y deja el código de la app (rutas, componentes, lógica) reunido bajo `src/`.

```text
src/app/
├── _layout.tsx       # root layout: wraps every screen
├── index.tsx         # route "/"
├── about.tsx         # route "/about"
└── note/
    └── [id].tsx      # route "/note/:id", for example "/note/42"
```

Tres convenciones de nombres:

- `index.tsx` es la ruta por defecto de su carpeta. `src/app/index.tsx` es la primera pantalla que ves al abrir la app.
- `_layout.tsx` no es una pantalla: es el **layout** que envuelve a las pantallas de su carpeta y decide cómo se navega entre ellas (en pila, en tabs, etc.).
- Un nombre entre corchetes, como `[id].tsx`, es una **ruta dinámica**: coincide con cualquier valor en ese segmento y lo entrega como parámetro.

Todo lo que no es una pantalla (componentes, datos, utilidades) va fuera de `src/app/`, por ejemplo en `src/components/`. Si lo pones dentro, Expo Router lo intentaría tratar como una ruta.

### El layout raíz con Stack

```tsx
// src/app/_layout.tsx
import { Stack } from "expo-router";

export default function RootLayout() {
  return <Stack />;
}
```

`Stack` apila las pantallas con la animación nativa de cada plataforma y dibuja una barra superior (header) con el título y el botón de volver. No tienes que registrar las pantallas: `Stack` descubre las rutas por los archivos. Expo Router además agrega por ti el `SafeAreaProvider` que viste en la lección de dimensiones.

### Navegar con Link y router

```tsx
// src/app/index.tsx
import { View, Text, Pressable } from "react-native";
import { Link, router } from "expo-router";

export default function Home() {
  return (
    <View style={{ flex: 1, padding: 16, gap: 12 }}>
      <Link href="/note/1">Abrir la nota 1</Link>
      <Link href={{ pathname: "/note/[id]", params: { id: "2" } }} asChild>
        <Pressable>
          <Text>Abrir la nota 2</Text>
        </Pressable>
      </Link>
      <Pressable onPress={() => router.push("/about")}>
        <Text>Acerca de</Text>
      </Pressable>
    </View>
  );
}
```

- `Link` es un texto tocable que navega a `href`. Puedes escribir la ruta completa (`"/note/1"`) o un objeto con `pathname` y `params`, que evita armar la cadena a mano.
- `asChild` hace que `Link` no dibuje su propio texto y pase la navegación a su hijo, por ejemplo un `Pressable` con tu diseño.
- `router.push(ruta)` navega desde código, útil después de guardar un formulario. `router.back()` vuelve a la pantalla anterior.

### Leer el parámetro de una ruta dinámica

```tsx
// src/app/note/[id].tsx
import { Text, View } from "react-native";
import { Stack, useLocalSearchParams } from "expo-router";

export default function NoteDetail() {
  const { id } = useLocalSearchParams<{ id: string }>();

  return (
    <View style={{ flex: 1, padding: 16 }}>
      <Stack.Screen options={{ title: "Nota " + id }} />
      <Text>Estás viendo la nota {id}</Text>
    </View>
  );
}
```

- `useLocalSearchParams` devuelve los parámetros de la ruta actual. El nombre `id` sale del nombre del archivo `[id].tsx`.
- Los parámetros siempre llegan como **texto**. Si tus ids son números, conviértelos con `Number(id)`.
- `Stack.Screen` dentro de una pantalla configura su header: aquí cambia el título según la nota.

### Qué no cabe en un Snack

Expo Router necesita varios archivos, así que no se puede ejecutar en el `App.tsx` único de un Snack. Por eso la práctica tiene dos partes: la terminal para crear los archivos en tu proyecto y un Snack que imita, con state, lo que el `Stack` hace por ti. Ver la versión manual te ayuda a entender qué automatiza el router.

## Errores comunes

**Poner componentes dentro de src/app.** Aparece una pantalla nueva e inesperada, o una advertencia de que un archivo no exporta un componente por defecto. Ocurre porque Expo Router trata cada archivo de `src/app/` como una ruta. Se detecta porque el nombre del componente aparece como ruta en la navegación o en la advertencia de Metro. Solución: mueve los componentes reutilizables a `src/components/`.

**Tratar el parámetro como número.** Comparas `note.id === id` con ids numéricos y nunca encuentras la nota. Ocurre porque `useLocalSearchParams` siempre entrega texto. Se detecta porque la pantalla de detalle muestra "No encontrada" aunque el id existe. Solución: guarda ids como texto o convierte con `Number(id)` antes de comparar.

**Olvidar el prefijo / en href.** Escribes `href="note/1"` y la navegación va a una ruta relativa inesperada o a la pantalla de "no encontrada". Ocurre porque sin la barra inicial la ruta se interpreta respecto a la pantalla actual. Se detecta porque la URL que muestra el error no coincide con la esperada. Solución: usa rutas absolutas como `"/note/1"` o el objeto con `pathname`.
