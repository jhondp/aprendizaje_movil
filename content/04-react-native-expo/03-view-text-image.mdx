## Objetivo

Al terminar esta lección podrás construir una pantalla combinando `View`, `Text` e `Image`, y explicar en qué se diferencian de `div`, `span` e `img`.

**Prerrequisitos:** `04-react-native-expo/02-expo-go-y-dev-client`

## Concepto

En la web tienes cientos de etiquetas HTML. En React Native tienes un conjunto pequeño de **componentes core** que se importan desde `react-native` y se traducen a vistas nativas. Con tres de ellos ya puedes construir la mayoría de pantallas.

Documentación oficial: https://reactnative.dev/docs/components-and-apis

### Una analogía: cajas, etiquetas y fotos

Piensa en ordenar un armario. Usas **cajas** para agrupar cosas, **etiquetas** escritas para decir qué hay en cada caja y **fotos** pegadas para reconocerlas de un vistazo. Las cajas pueden contener otras cajas, etiquetas y fotos; una etiqueta solo contiene texto. En React Native, `View` es la caja, `Text` es la etiqueta e `Image` es la foto.

### View: el contenedor

`View` es el equivalente de `div`. Agrupa otros componentes y recibe estilos de layout, bordes y fondo.

```tsx
import { View } from "react-native";

export default function Box() {
  return <View style={{ padding: 16, backgroundColor: "#eef" }} />;
}
```

Dos diferencias con `div`:

- Por defecto sus hijos se apilan en **columna**, no en fila. Todo `View` es un contenedor Flexbox con `flexDirection: "column"`.
- No acepta texto suelto. Si escribes texto directamente dentro de un `View`, la app falla.

### Text: todo texto va aquí

En React Native **cualquier texto** debe estar dentro de un `Text`. No existe `p`, `h1` ni `span`: el tamaño y el peso se dan con estilos.

```tsx
import { Text } from "react-native";

export default function Title() {
  return (
    <Text style={{ fontSize: 22, fontWeight: "700" }}>
      Hola, <Text style={{ color: "tomato" }}>Ana</Text>
    </Text>
  );
}
```

Un `Text` puede anidar otros `Text`, y los hijos heredan el estilo del padre (por eso "Ana" mantiene el tamaño 22 y además es rojo). Esa herencia **solo ocurre entre `Text`**: un `View` no transmite `color` ni `fontSize` a sus hijos. No hay cascada de CSS.

`Text` tiene props útiles propias:

- `numberOfLines={2}` recorta el texto en dos líneas y agrega puntos suspensivos.
- `selectable` permite al usuario seleccionar y copiar el texto.

### Image: imágenes locales

`Image` muestra imágenes. Para una imagen que viene dentro del proyecto usas `require` con la ruta del archivo:

```tsx
import { Image } from "react-native";

export default function Avatar() {
  return (
    <Image
      source={require("../assets/avatar.png")}
      style={{ width: 96, height: 96, borderRadius: 48 }}
      accessibilityLabel="Foto de perfil"
    />
  );
}
```

- `require` se resuelve en tiempo de build: Metro empaqueta el archivo y conoce su tamaño.
- `style` define el tamaño en pantalla. Con `borderRadius` igual a la mitad del ancho obtienes un círculo.
- `resizeMode` controla cómo se ajusta la imagen a su caja: `"cover"` recorta para llenar, `"contain"` muestra la imagen completa.
- `accessibilityLabel` es el texto que lee el lector de pantalla, como el `alt` de la web.

Para imágenes remotas (una URL) Expo recomienda `expo-image`, que agrega caché en disco y mejor rendimiento. Lo verás en la lección de imágenes, fuentes e íconos; por ahora trabaja con imágenes locales.

### Unidades sin px

Los números de estilo no llevan unidad. `width: 96` significa 96 **puntos independientes de la densidad** (dp). Un teléfono con pantalla de alta densidad usa más píxeles físicos para esos 96 puntos, así que el tamaño visual es similar en todos los dispositivos.

### Juntar las piezas

Una tarjeta de perfil combina los tres componentes: un `View` como tarjeta, una `Image` para la foto y varios `Text` para nombre y descripción. Los estilos se agrupan con `StyleSheet.create`, que estudiarás en detalle en el módulo de estilos; por ahora tómalo como un objeto con nombres para cada estilo.

## Errores comunes

**Texto suelto dentro de un View.** La app muestra el error "Text strings must be rendered within a Text component". Ocurre porque en React Native solo `Text` sabe dibujar texto; en la web cualquier elemento lo acepta. Se detecta por ese mensaje exacto, que además indica el componente. También aparece con condicionales como `count && ...` cuando `count` vale `0`: el `0` se intenta renderizar como texto. Usa `count > 0 && ...`.

**Esperar que un View herede estilos de texto.** Pones `color: "red"` en un `View` y el texto de adentro sigue negro. Ocurre porque no hay cascada: los estilos de texto solo se heredan de un `Text` a sus `Text` hijos. Se detecta porque el estilo no tiene efecto. Solución: aplica el estilo al `Text` o anida los `Text`.

**Imagen que no aparece.** La `Image` no muestra nada y no hay error. Ocurre con imágenes remotas sin `width` y `height`: React Native no conoce su tamaño y las dibuja con tamaño cero. Se detecta poniendo un `backgroundColor` temporal a la imagen para ver su caja. Solución: define siempre el tamaño en `style`.
