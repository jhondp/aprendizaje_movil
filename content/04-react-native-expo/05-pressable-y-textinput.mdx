## Objetivo

Al terminar esta lección podrás crear botones con `Pressable` que reaccionan al toque y un campo `TextInput` controlado que agrega elementos a una lista.

**Prerrequisitos:** `04-react-native-expo/04-scrollview-y-flatlist`

## Concepto

En la web, casi cualquier elemento acepta `onClick` y tienes `input` para escribir. En React Native, `View` y `Text` no responden a toques por sí solos: necesitas componentes diseñados para la interacción. Los dos principales son `Pressable` y `TextInput`.

Documentación oficial: https://reactnative.dev/docs/pressable y https://reactnative.dev/docs/textinput

### Una analogía: el timbre y el formulario en papel

Un timbre no hace nada hasta que alguien lo presiona, y cuando lo haces notas que se hunde: te confirma que lo tocaste. `Pressable` es ese timbre: una caja que detecta el toque y te deja cambiar su aspecto mientras está presionada.

Un formulario en papel tiene una casilla donde escribes, pero quien decide qué queda anotado eres tú. Un `TextInput` controlado funciona igual: el teclado propone texto y tu state decide qué se muestra.

### Pressable

`Pressable` envuelve cualquier contenido y detecta toques.

```tsx
import { Pressable, Text } from "react-native";

export default function SaveButton({ onSave }: { onSave: () => void }) {
  return (
    <Pressable
      onPress={onSave}
      accessibilityRole="button"
      style={({ pressed }) => ({
        padding: 12,
        borderRadius: 8,
        backgroundColor: pressed ? "#0056b3" : "#007aff",
      })}
    >
      <Text style={{ color: "#fff", fontWeight: "600" }}>Guardar</Text>
    </Pressable>
  );
}
```

Lo importante:

- `onPress` se ejecuta cuando el usuario toca y suelta dentro del área. Es el equivalente a `onClick`.
- `style` puede ser una **función** que recibe `{ pressed }`. Así das respuesta visual mientras el dedo está encima, algo esencial en móvil porque no existe el estado hover.
- `onLongPress` se ejecuta con una pulsación prolongada.
- `hitSlop={8}` amplía el área táctil 8 puntos hacia cada lado sin cambiar el tamaño visible. Útil para íconos pequeños.
- `disabled` desactiva el toque.
- `accessibilityRole="button"` le dice al lector de pantalla que es un botón.

React Native también trae `Button`, un botón sencillo con el estilo del sistema que no se puede personalizar mucho. En guías antiguas verás `TouchableOpacity`; hoy la documentación recomienda `Pressable` porque es más flexible y es la base sobre la que se construyen los demás.

### TextInput controlado

`TextInput` es el campo de texto. Igual que en la etapa de React, lo controlas con state:

```tsx
import { useState } from "react";
import { TextInput } from "react-native";

export default function NameField() {
  const [name, setName] = useState("");

  return (
    <TextInput
      value={name}
      onChangeText={setName}
      placeholder="Tu nombre"
      autoCapitalize="words"
      style={{ borderWidth: 1, borderColor: "#ccc", borderRadius: 8, padding: 12 }}
    />
  );
}
```

La diferencia clave con la web: `onChangeText` recibe **directamente el texto nuevo**, no un evento. Por eso puedes pasar `setName` sin envolverlo. Existe también `onChange`, que recibe un evento, pero `onChangeText` es lo habitual.

Otras props que configuran el teclado del teléfono:

- `keyboardType`: `"default"`, `"email-address"`, `"numeric"`, `"phone-pad"`. Cambia el teclado que aparece.
- `autoCapitalize`: `"none"`, `"sentences"`, `"words"`. Para correos usa `"none"`.
- `secureTextEntry`: oculta el texto, para contraseñas.
- `returnKeyType`: la etiqueta de la tecla Enter, por ejemplo `"done"` o `"send"`.
- `onSubmitEditing`: se ejecuta cuando el usuario pulsa esa tecla.
- `multiline`: permite varias líneas, útil para el cuerpo de una nota.

Por defecto el `TextInput` no tiene borde ni fondo: si no le das estilo, es casi invisible.

### Juntar ambos

El patrón para agregar elementos a una lista es el mismo que en la web: un state para el texto, otro para la lista, y una función que crea el elemento nuevo, lo agrega de forma inmutable y limpia el campo. Lo único nuevo son los componentes. Valida siempre que el texto no esté vacío antes de agregar: `text.trim()` elimina los espacios de los extremos.

## Errores comunes

**Usar onChange como en la web.** Escribes `onChange={(e) => setText(e.target.value)}` y obtienes `undefined` o un error. Ocurre porque en React Native el evento no tiene `target.value`. Se detecta porque el campo no se actualiza o TypeScript marca que `value` no existe. Solución: `onChangeText={setText}`.

**Poner onPress en un View o un Text para todo.** `Text` acepta `onPress`, pero no da respuesta visual ni se comporta como botón para la accesibilidad, y `View` no acepta `onPress`. Ocurre por costumbre de la web, donde cualquier elemento recibe `onClick`. Se detecta porque el toque no produce ninguna reacción visual. Solución: envolver en `Pressable` con `accessibilityRole="button"`.

**Campo de texto invisible.** Agregas un `TextInput` y no lo ves en pantalla. Ocurre porque por defecto no tiene borde, fondo ni altura mínima visible. Se detecta tocando la zona y viendo aparecer el teclado. Solución: dale `borderWidth`, `padding` y un color de borde.
