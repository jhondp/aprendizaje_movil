## Objetivo

Al terminar esta lección tendrás una app de notas con Expo Router que lista, muestra, crea y edita notas, con el estado en un provider de nivel superior y la interfaz protegida por las áreas seguras.

**Prerrequisitos:** `04-react-native-expo/10-tabs-stack-y-plataformas`

## Concepto

Este proyecto junta todo lo de la etapa en una app real. Es la versión móvil del [tablero de tareas](/etapa/03-react/11-proyecto-tablero-de-tareas) que construiste al cerrar la etapa de React: la misma idea de una lista que el usuario modifica, ahora con componentes nativos, varias pantallas y navegación. La etapa 5 conectará esta app a persistencia y a una arquitectura por capas, así que conviene que quede ordenada.

Documentación de referencia: https://docs.expo.dev/router/introduction/ y https://react.dev/reference/react/useContext

### Una analogía: la libreta y sus páginas

Piensa en una libreta de notas con un índice al principio. El índice (la lista) te dice qué notas hay; abres una página (el detalle) para leerla; tachas y reescribes una página (la edición). Hay una sola libreta: si corriges una nota en su página, el índice también cambia, porque ambos miran el mismo papel. En la app, esa libreta única es el **provider**: todas las pantallas leen y modifican las mismas notas.

### Qué vas a construir

Una app con tres pantallas:

1. **Lista** (`/`): todas las notas, con un botón para crear una nueva. Si no hay notas, un mensaje lo indica.
2. **Detalle** (`/note/[id]`): el título y el contenido de una nota, con un botón para editarla.
3. **Edición** (`/edit`): un formulario con título y contenido. Sin parámetro crea una nota; con `?id=3` edita la nota 3. El botón Guardar se desactiva si el título está vacío.

Las notas viven en memoria: al cerrar la app se pierden. Es intencional; guardarlas en el dispositivo es el primer tema de la etapa 5.

### Estructura de archivos

```text
my-notes/
└── src/
    ├── app/
    │   ├── _layout.tsx      # NotesProvider + root Stack
    │   ├── index.tsx        # "/" : notes list
    │   ├── edit.tsx         # "/edit" and "/edit?id=3" : create or edit
    │   └── note/
    │       └── [id].tsx     # "/note/:id" : note detail
    └── notes/
        └── NotesContext.tsx # notes state, shared by every screen
```

`NotesContext.tsx` está fuera de `src/app/` porque no es una pantalla, como viste en la lección de Expo Router.

### El provider de notas

El estado vive en un Context de React, igual que en la etapa anterior. El provider expone la lista y dos acciones; el hook `useNotes` falla con un mensaje claro si alguien lo usa fuera del provider.

```tsx
// src/notes/NotesContext.tsx
import { createContext, useContext, useState, type ReactNode } from "react";

export type Note = { id: string; title: string; body: string };

type NotesContextValue = {
  notes: Note[];
  addNote: (title: string, body: string) => string;
  updateNote: (id: string, title: string, body: string) => void;
};

const NotesContext = createContext<NotesContextValue | null>(null);

export function NotesProvider({ children }: { children: ReactNode }) {
  const [notes, setNotes] = useState<Note[]>([]);

  function addNote(title: string, body: string) {
    const id = String(Date.now());
    setNotes((prev) => [{ id, title, body }, ...prev]);
    return id;
  }

  function updateNote(id: string, title: string, body: string) {
    setNotes((prev) => prev.map((note) => (note.id === id ? { ...note, title, body } : note)));
  }

  return (
    <NotesContext.Provider value={{ notes, addNote, updateNote }}>{children}</NotesContext.Provider>
  );
}

export function useNotes() {
  const value = useContext(NotesContext);
  if (!value) throw new Error("useNotes must be used inside NotesProvider");
  return value;
}
```

### El layout raíz

El provider envuelve al `Stack`, así todas las pantallas comparten las mismas notas. La edición se presenta como modal: en iOS sube desde abajo.

```tsx
// src/app/_layout.tsx
import { Stack } from "expo-router";
import { NotesProvider } from "../notes/NotesContext";

export default function RootLayout() {
  return (
    <NotesProvider>
      <Stack>
        <Stack.Screen name="index" options={{ title: "Notas" }} />
        <Stack.Screen name="note/[id]" options={{ title: "Nota" }} />
        <Stack.Screen name="edit" options={{ title: "Editar", presentation: "modal" }} />
      </Stack>
    </NotesProvider>
  );
}
```

### La lista

El header del `Stack` ya protege el borde superior. El botón inferior suma el inset de la barra de gestos con `useSafeAreaInsets`.

```tsx
// src/app/index.tsx
import { FlatList, Pressable, StyleSheet, Text, View } from "react-native";
import { Link } from "expo-router";
import { useSafeAreaInsets } from "react-native-safe-area-context";
import { useNotes } from "../notes/NotesContext";

export default function NotesList() {
  const { notes } = useNotes();
  const insets = useSafeAreaInsets();

  return (
    <View style={styles.screen}>
      <FlatList
        data={notes}
        keyExtractor={(item) => item.id}
        renderItem={({ item }) => (
          <Link href={{ pathname: "/note/[id]", params: { id: item.id } }} asChild>
```

### El detalle

```tsx
// src/app/note/[id].tsx
import { Pressable, StyleSheet, Text, View } from "react-native";
import { Link, Stack, useLocalSearchParams } from "expo-router";
import { useNotes } from "../../notes/NotesContext";

export default function NoteDetail() {
  const { id } = useLocalSearchParams<{ id: string }>();
  const note = useNotes().notes.find((item) => item.id === id);

  if (!note) return <Text style={styles.body}>No encontramos esta nota.</Text>;

  return (
    <View style={styles.screen}>
      <Stack.Screen options={{ title: note.title }} />
      <Text style={styles.body}>{note.body || "Sin contenido"}</Text>
      <Link href={{ pathname: "/edit", params: { id: note.id } }} asChild>
        <Pressable style={styles.button}>
          <Text style={styles.buttonText}>Editar</Text>
        </Pressable>
      </Link>
    </View>
  );
}

const styles = StyleSheet.create({
  screen: { flex: 1, padding: 16, gap: 16, backgroundColor: "#fff" },
  body: { fontSize: 17, lineHeight: 24, padding: 16 },
  button: { padding: 14, borderRadius: 12, alignItems: "center", backgroundColor: "#007aff" },
  buttonText: { color: "#fff", fontSize: 17, fontWeight: "600" },
});
```

### La edición

Una sola pantalla crea y edita: si llega un `id`, precarga la nota. Al guardar, `router.back()` cierra el modal.

```tsx
// src/app/edit.tsx
import { useState } from "react";
import { Pressable, StyleSheet, Text, TextInput, View } from "react-native";
import { router, useLocalSearchParams } from "expo-router";
import { useNotes } from "../notes/NotesContext";

export default function EditNote() {
  const { id } = useLocalSearchParams<{ id?: string }>();
  const { notes, addNote, updateNote } = useNotes();
  const existing = notes.find((note) => note.id === id);
  const [title, setTitle] = useState(existing?.title ?? "");
  const [body, setBody] = useState(existing?.body ?? "");
  const canSave = title.trim().length > 0;

  function save() {
    if (!canSave) return;
    if (existing) updateNote(existing.id, title.trim(), body);
    else addNote(title.trim(), body);
    router.back();
  }

  return (
    <View style={styles.screen}>
      <TextInput style={styles.input} value={title} onChangeText={setTitle} placeholder="Título" />
      <TextInput
        style={[styles.input, styles.multiline]}
        value={body}
        onChangeText={setBody}
        placeholder="Contenido"
        multiline
      />
      <Pressable style={[styles.button, !canSave && styles.disabled]} disabled={!canSave} onPress={save}>
        <Text style={styles.buttonText}>Guardar</Text>
      </Pressable>
    </View>
  );
}

const styles = StyleSheet.create({
  screen: { flex: 1, padding: 16, gap: 12, backgroundColor: "#fff" },
  input: { borderWidth: 1, borderColor: "#ccc", borderRadius: 8, padding: 12, fontSize: 16 },
  multiline: { minHeight: 160, textAlignVertical: "top" },
  button: { padding: 14, borderRadius: 12, alignItems: "center", backgroundColor: "#007aff" },
  disabled: { backgroundColor: "#a0c4ff" },
  buttonText: { color: "#fff", fontSize: 17, fontWeight: "600" },
});
```

`textAlignVertical: "top"` es un ejemplo de detalle de plataforma: en Android el texto de un campo multilínea aparece centrado en vertical si no lo indicas.

### Qué significa "terminado"

La app está terminada cuando cumple todos los requisitos de la lista de la práctica en un teléfono o emulador real, no solo en la vista web. Prueba en especial: crear una nota, abrirla, editarla y volver a la lista viendo el título nuevo sin recargar.

## Errores comunes

**Usar useNotes en una pantalla que no está dentro del provider.** La app muestra el error "useNotes must be used inside NotesProvider". Ocurre cuando el provider envuelve solo una parte del árbol, o cuando se olvida en `_layout.tsx`. Se detecta por ese mensaje, que existe justamente para eso. Solución: el `NotesProvider` va en el layout raíz, envolviendo al `Stack`.

**El formulario de edición muestra datos viejos.** Abres la edición de una nota y los campos aparecen vacíos o con otra nota. Ocurre porque `useState(existing?.title ?? "")` solo usa su valor inicial al montar la pantalla; si la pantalla se reutiliza con otro `id`, el state no cambia solo. Se detecta editando dos notas seguidas. Solución: que cada edición monte la pantalla de nuevo, como hace el modal de este proyecto al cerrarse con `router.back()`.

**Mutar la lista en lugar de crear una nueva.** Editas `note.title = title` dentro del arreglo y la lista no se actualiza. Ocurre porque React compara referencias: si el arreglo es el mismo, no vuelve a renderizar. Se detecta porque el cambio solo aparece al tocar otra cosa. Solución: `map` y `filter` devuelven arreglos nuevos, como en las funciones puras del ejercicio.
