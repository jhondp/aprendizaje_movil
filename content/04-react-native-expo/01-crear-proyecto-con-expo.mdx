## Objetivo

Al terminar esta lección podrás crear un proyecto nuevo con Expo, arrancar el servidor de desarrollo y ver tus cambios en un teléfono o un emulador.

**Prerrequisitos:** `04-react-native-expo/00-como-funciona-react-native`

## Concepto

React Native por sí solo te da el motor: componentes core, renderizado nativo y Hermes. Para construir una app real necesitas mucho más: herramientas para compilar, acceso a la cámara o a las notificaciones, navegación, un servidor de desarrollo. **Expo** es el framework que reúne todo eso. La documentación oficial de React Native recomienda empezar cualquier proyecto nuevo con un framework, y Expo es el recomendado.

Documentación oficial: https://docs.expo.dev/get-started/create-a-project/

### Una analogía: la cocina equipada

Puedes montar una cocina comprando cada pieza por separado: horno, extractor, cañerías, instalación eléctrica. O puedes alquilar una cocina profesional que ya trae todo conectado y probado. React Native es el horno. Expo es la cocina equipada: sigues cocinando tú, pero no pierdes una semana instalando cañerías.

### Crear el proyecto

Necesitas Node.js LTS (la versión 22 o superior) instalado en tu computadora. Luego ejecutas:

```bash
npx create-expo-app@latest my-notes
```

- `npx` descarga y ejecuta la herramienta sin instalarla de forma global.
- `@latest` garantiza que usas la versión más reciente de la plantilla y, por lo tanto, el SDK de Expo más reciente.
- `my-notes` es el nombre de la carpeta que se crea.

La herramienta descarga la plantilla por defecto e instala las dependencias con npm.

### La estructura del proyecto

La plantilla por defecto cambia un poco entre versiones del SDK, pero la idea central se mantiene. Las piezas que importan ahora son estas:

```text
my-notes/
├── app.json          # app name, icon, splash screen, native config
├── package.json      # dependencies and scripts
├── tsconfig.json     # TypeScript is enabled by default
├── assets/           # images and fonts
└── src/
    ├── app/          # screens: every file here is a route
    │   ├── _layout.tsx
    │   └── index.tsx
    └── components/   # reusable components
```

- `app.json` describe la app: nombre, ícono, pantalla de carga, identificadores de iOS y Android.
- `src/app/` contiene las pantallas. Expo Router convierte cada archivo en una ruta; lo estudiarás en el módulo de navegación. Proyectos creados con SDK anteriores al 55 tienen esta carpeta en `app/`, en la raíz; ambas ubicaciones funcionan.
- `src/app/index.tsx` es la primera pantalla que ves al abrir la app.

Por ahora basta con saber que puedes editar `src/app/index.tsx` y ver el resultado.

### Arrancar el servidor de desarrollo

```bash
cd my-notes
npx expo start
```

Este comando arranca **Metro**, el bundler de React Native. Metro cumple el mismo papel que Vite en la etapa de React: toma todos tus archivos, los transforma y los sirve como un bundle. En la terminal aparece un código QR y un menú de atajos:

- `a` abre la app en un emulador de Android.
- `i` abre la app en el simulador de iOS (solo en macOS con Xcode).
- `w` abre la app en el navegador.
- `r` recarga la app.
- `j` abre las herramientas de depuración.

### Abrir la app en tu teléfono

La forma más rápida de ver la app en un dispositivo real es **Expo Go**, una app que ya trae compilado el SDK de Expo y puede cargar tu bundle de JavaScript. Escaneas el código QR, Expo Go descarga el bundle desde Metro y tu app aparece.

Hay tres condiciones:

1. El teléfono y la computadora deben estar en la misma red Wi-Fi. Si tu red bloquea la conexión, usa `npx expo start --tunnel`.
2. Expo Go soporta un solo SDK por versión. Si tu proyecto usa un SDK más nuevo que el Expo Go de la tienda, la app muestra un error de incompatibilidad.
3. En iOS, para los SDK más recientes Expo Go puede no estar aún en la App Store. La página https://docs.expo.dev/get-started/expo-go/ explica cómo instalar la versión correcta; si no puedes hacerlo, usa un emulador de Android o la vista web mientras tanto.

### Fast Refresh

Con la app abierta, edita el texto de `src/app/index.tsx` y guarda. El cambio aparece en el teléfono en menos de un segundo y el state de la pantalla se conserva. Esto se llama **Fast Refresh**. Si cometes un error de sintaxis, aparece una pantalla roja con el archivo y la línea; al corregirlo, desaparece sola.

## Errores comunes

**El teléfono no conecta con Metro.** Expo Go queda cargando o muestra "Could not connect to development server". Ocurre porque el teléfono y la computadora están en redes distintas, o porque una VPN o un firewall bloquean el puerto 8081. Se detecta comparando la IP del mensaje `exp://` con la red del teléfono. Solución: misma red Wi-Fi o `npx expo start --tunnel`.

**Expo Go dice que el proyecto es incompatible.** Aparece un mensaje que menciona la versión del SDK. Ocurre porque Expo Go soporta un solo SDK y tu proyecto usa otro. Se detecta comparando el campo `expo` de `package.json` con la versión que indica Expo Go. Solución: instalar la versión de Expo Go que corresponde, usar un emulador o, más adelante, un development build.

**Instalar paquetes globales antiguos.** Guías viejas piden `npm install -g expo-cli`. Esa herramienta está retirada; la CLI actual viene dentro del proyecto y se ejecuta con `npx expo`. Se detecta porque el comando `expo` global muestra advertencias de deprecación.
