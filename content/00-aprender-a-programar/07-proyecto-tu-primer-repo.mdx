## Objetivo

Al terminar esta lección vas a tener un repositorio propio en GitHub, con un README que explica qué quieres construir, un archivo `.gitignore` y al menos dos commits en su historia.

**Prerrequisitos:** `00-aprender-a-programar/06-ia-con-criterio`

## Concepto

Esta lección no enseña un concepto nuevo: junta todo lo que aprendiste en esta etapa (la terminal, VS Code y Node.js, Git y GitHub, leer documentación y usar IA con criterio) en un solo proyecto real. Es como la primera vez que cocinas una receta completa tú solo, sin que nadie te indique cada paso: ya conoces cada ingrediente por separado, ahora los combinas en orden.

Tu proyecto es un repositorio que describe, en un README, qué quieres construir durante el resto del curso. No hace falta que sea una idea original ni definitiva: puedes cambiarla más adelante. Lo que importa ahora es practicar el flujo completo con un contenido real, propio, en lugar de un ejemplo inventado.

### Las tres piezas que te faltan

- **README.md**: el primer archivo que alguien lee al entrar a tu repositorio en GitHub. Se escribe en Markdown (el mismo formato con el que están escritas estas lecciones) y normalmente responde qué es el proyecto, por qué existe y cómo se usa. GitHub lo muestra automáticamente en la página principal del repositorio.
- **.gitignore**: una lista de archivos y carpetas que Git debe ignorar, es decir, nunca incluir en un commit. Se usa para no subir cosas como dependencias descargadas, archivos temporales o contraseñas. Es un archivo de texto plano, un patrón por línea; por ejemplo, la línea `node_modules/` le dice a Git que ignore esa carpeta completa.
- **Historia con más de un commit**: un repositorio con un solo commit no demuestra que sabes iterar. Vas a hacer un primer commit con el README, y un segundo commit después de agregar o corregir algo, para practicar el ciclo completo: editar, `git add`, `git commit`.

Puedes repasar la guía oficial de primeros pasos con GitHub en [docs.github.com/es/get-started](https://docs.github.com/es/get-started) si algún paso no te resulta claro.

<Callout kind="tip">
  Si no tienes todavía una idea de proyecto, describe en el README algo simple y concreto: por ejemplo, "una lista de tareas" o "una calculadora de propinas". La idea puede cambiar; lo que no cambia es el hábito de documentarla desde el primer commit.
</Callout>

## Errores comunes

- **Crear el repositorio en GitHub antes que el local, y no saber cómo conectarlos.** El flujo de esta lección crea primero el repositorio local con `git init -b main` y recién después lo conecta con `git remote add origin`. Cómo detectarlo: si ya creaste el repositorio vacío en GitHub, la página te muestra exactamente el comando `git remote add origin` con tu URL; cópialo desde ahí.
- **Agregar `.gitignore` después de haber subido los archivos que quería ignorar.** Un `.gitignore` solo afecta a archivos que Git todavía no está rastreando; si `node_modules` ya fue subida en un commit anterior, agregar la línea no la elimina del historial. Cómo detectarlo: ejecuta `git ls-files node_modules` después de crear el `.gitignore`; si lista archivos, Git los sigue rastreando y tienes que dejar de rastrearlos con `git rm -r --cached node_modules` y un nuevo commit.
- **Ejecutar `git init` sin `-b main`.** Git crea la rama `master` y el primer `git push -u origin main` falla con "src refspec main does not match any". Cómo detectarlo: `git branch` muestra `* master`; ejecuta `git branch -M main` antes del push.
- **Escribir el README en inglés o dejarlo vacío.** El objetivo de esta lección es practicar documentar tu propia idea, no copiar una plantilla. Cómo detectarlo: si el README no menciona qué construye el proyecto ni por qué, todavía no cumple el objetivo de la lección.
